# Changelog

## [Unreleased]

### Добавлено

- **Потолок UDP-сессий sing-box** — в панели движка можно ограничить число одновременных UDP-сессий (`udp_nat_max`); при переполнении вытесняется самая старая. Полезно на роутерах с малой памятью.
- **Таймаут DNS-запроса** — в модале «DNS по умолчанию» (sb-router и fakeip) задаётся, сколько ждать ответ одного сервера; пусто — 10 с движка.
- **Правило по MAC устройства** — в редакторе правила sb-router появилось поле «MAC устройства» (`source_mac_address`, sing-box 1.14): правило срабатывает для LAN-устройства по адресу из таблицы соседей роутера, без привязки к IP.
- **Optimistic DNS-кэш** — протухший ответ отдаётся сразу, обновление идёт в фоне; при cache.db в tmp кэш DNS переживает перезапуск движка (`store_dns`).

### Изменено

- **Встроенный sing-box обновлён до 1.14.0-awgm.16** — форк перенесён с `1.14.0-rc.1` на релизный upstream `v1.14.0`. Из апстрима между rc.1 и релизом: починено управление перегрузкой QUIC (hysteria2, TUIC), паника при неудачном handshake WebSocket, early data WebSocket под smux/yamux, переиспользование портов TCP NAT в стеке `system`, защита TUN от петли в `direct`; Go 1.26.7. В сборку возвращён inbound `cloudflared` (запрос в форк, issue #7); mieru внутри движка обновлён до 3.36.1. Загрузка наборов правил переведена с deprecated download_detour на http_clients: общий клиент идёт через выход «по умолчанию» (final), без него — напрямую; в 1.16 старая форма перестанет работать (существующие конфиги переписываются при первом запуске). Из tun-inbound убраны ключи gso (удалён sing-box ещё в 1.12) и endpoint_independent_nat (удалён в 1.14) (первый с true ронял движок, второй заменён udp_mapping/udp_filtering).

### Исправлено

- **Остатки после `opkg remove awg-manager` (#854).** Пакет при удалении снимает все свои хуки в `/opt/etc/ndm/netfilter.d`, каталоги `/opt/var/lock/awg-manager` и `/opt/var/run/awg-manager`, логи и недокачанный IPK в `/opt/tmp`. Остаются только `/opt/etc/awg-manager` и файл репозитория, подсказка ведёт на раздел «Полное удаление» документации. Лог stderr демона и замок хранилища туннелей переехали с накопителя в `/var/run/awg-manager` (RAM): замок больше не пишет на флеш при каждом изменении туннеля и не переживает перезагрузку.
- **Ложное «Нет связи» на карточке туннеля.** Фоновая проверка связи стучалась на зашитый `connectivitycheck.gstatic.com:443`, игнорируя адрес проверки из настроек, — кнопка «Тест» и curl через туннель отвечали «работает», а карточка через минуту снова краснела. Теперь фоновая проверка делает тот же HTTP-запрос по настроенному адресу, что и кнопка «Тест», — расходиться им больше нечем.
- **Удаление клиента управляемого сервера при недоступном роутере.** Раньше при ошибке RCI клиент исчезал с карточки, но оставался на роутере и продолжал ходить через сервер. Теперь удаление отказывает (ответ 400), клиент остаётся в списке — повторите позже. Толерантности к «клиента уже нет на роутере» нет: если роутер отвечает ошибкой на снятие отсутствующего пира, удалите его из NDMS вручную.
- **Ключ `--pprof-on-main` удалён.** Профилировщик на основном HTTP-порту отдавал дампы кучи (с токенами сессий и ключами) без авторизации. Профилирование доступно только через `--pprof-listen` на loopback.
- **Вход в панель после загрузки роутера.** Если при первом входе NDMS ещё не отвечал, адрес и порт роутера фиксировались догадкой «192.168.1.1:80» до перезапуска демона, и на роутерах с `ip http port` не 80 вход не работал. Теперь адрес запоминается только после удачного чтения порта.
- **Настройки NDMS не терялись на перезагрузке при обрыве связи с роутером.** Если команда роутеру применилась, а ответ не доехал (таймаут), сохранение в startup-config не запрашивалось. Теперь сохранение и сброс кэшей идут и при ошибке транспорта. Побочно: индикатор сохранения может показать «ошибка» при недоступном роутере — он сбросится следующим успешным сохранением.
- **Место хранения cache.db.** Если запись настройки не удалась после того, как новый путь уже применён к конфигурации sing-box, база и настройки расходились до следующего изменения. Теперь применение откатывается к прежнему пути.
- **Проверка конфигурации sing-box.** Опечатка в теге DNS-сервера у AWG-исходящего (`domain_resolver.server`) теперь ловится валидатором, а не роняет sing-box при загрузке.
- **Файловый менеджер.** Запись и удаление в read-only корне отвечают 403, а не 400.
- **Скрипты init.d.** Удаление выключенного (K-) скрипта больше не исполняет его; останавливаются только включённые (S-). Отказ действия над службой пишется в журнал как предупреждение, а не как «выполнено».
- **Управляемые серверы.** Отказ перезапуска сервера виден в журнале и обновляет карточку вместо вечного «перезапускается»; деградация static-NAT до одного WAN (running-config недоступен или без `ip global`) пишется в журнал приложения.
- **DNS-маршруты: массовая смена бэкенда** отвечает ошибкой, если не удалось поменять ни один список (раньше — 200 и событие, как будто что-то изменилось).
- **Карантин повреждённого settings.json** честно сообщает, если файл не удалось переместить в `.corrupt`.
- **Пиры сервера.** Сгенерированный ключ проверяется по форме перед отправкой на роутер; отказ снятия секрета пира больше не теряется молча.
- **Состояние туннеля на KeeneticOS 4.x.** Поле `interfaceUp` в API заполняется из состояния линка.
- **Удаление туннеля на KeeneticOS 5.x.** Отказ снятия host-route до VPN-сервера попадает в журнал.
- **Замок каталога данных.** Лок живого процесса больше не снимается по возрасту; снятие лока не задевает чужой.

## [2.18.0] - 2026-08-28

### Добавлено

- **Защита туннеля от изменений (#818).** Рядом с тумблером на карточке, в мелкой сетке и в списке появился замок. У защищённого туннеля тумблер погашен, а кнопки «Изменить» и «Удалить» недоступны: случайно выключить, переписать или снести рабочий туннель больше нельзя. Снимается защита тем же замком — с подтверждением, чтобы это не вышло само собой.

- **Раздел «Прокси»: выход через WDTT и FreeTurn и раздача его другим.** Прокси-клиенты и серверы переехали с главной страницы в собственный раздел с двумя вкладками: «Выход» — трафик роутера наружу через чужой сервер, «Раздача» — свой сервер для телефонов и других роутеров. Профиль добавляется ссылкой, файлом или JSON-подпиской: мастер сам разберёт её, выберет свободный порт, создаст AWG-туннель и заведёт интерфейс в политику доступа. Ссылка абоненту выдаётся тут же — отдельно для приложения на телефоне и для клиента на роутере. Прежние настройки переносятся при обновлении и помечены в интерфейсе, переделывать ничего не нужно.

### Исправлено

- **Домены резолвились мимо AWG-туннеля (#846).** Домен, отправленный в AWG-туннель правилом маршрутизации или прокси для устройства, роутер спрашивал у резолвера по умолчанию (`dns-bootstrap` в режимах TProxy и policy-tun, `real` в FakeIP) своим обычным маршрутом — мимо туннеля: запрос видел провайдер, а ответ мог быть подменённым. Теперь у каждого AWG-туннеля свой DNS-сервер: первый IPv4 из поля DNS туннеля, а если поле пустое — `1.1.1.1`; сам запрос идёт через этот же туннель. Если туннель лежит, резолв падает, а не утекает наружу. Для split-туннеля (в AllowedIPs не `0.0.0.0/0`) адрес DNS должен попадать в AllowedIPs пира, иначе резолв через туннель невозможен — задайте подходящий DNS в настройках туннеля.
- **Смена WAN-подключения на карточке туннеля** - больше не обнуляет связь туннеля с WDTT/FreeTurn-клиентом. Заодно правка карточки перестала откатывать то, что за время её применения записали другие подсистемы.
- **Режимы FakeIP и policy-tun не включались на KeeneticOS 5.00 (#828).** Разрешение межсетевого экрана для IPv6 (`ipv6 access-list`) появилось только в 5.01 — на прошивках старше роутер отвечал «нет такой команды», и включение режима падало целиком: из выключенного состояния — ошибкой создания OpkgTun, из работающего TProxy — откатом обратно в TProxy. Теперь такой отказ провалом не считается: на этих прошивках фильтровать IPv6 на туннельном интерфейсе всё равно нечем.

## [2.17.3] - 2026-08-22

### Добавлено

- **Адрес bootstrap-резолвера sing-box настраивается из UI (#770).** В `00-base.json` жил жёстко зашитый `1.1.1.1`, а именно этим резолвером sing-box превращает доменные адреса в IP: endpoint'ы туннелей, серверы подписок, апстримы DNS-серверов. У части мобильных операторов этот адрес нестабилен или заблокирован — и тогда движок не дотягивается ни до одного сервера с доменным именем, а в журнале копятся ошибки DNS.

- **Sing-box можно удалить из UI (#771).** Раньше кнопка была только на установку: поставил движок — живи с ним. Теперь в «Настройки → Интеграции» рядом с «Открыть» есть «Удалить»: движок останавливается, а его каталог удаляется целиком — бинарь, конфигурация `config.d`, кэш FakeIP и журналы процесса.

- **Привязка исходящего интерфейса (egress bind) для подписок и ручных туннелей (#709)** — теперь для любой подписки и ручного прокси-туннеля sing-box можно явно указать сетевой интерфейс (`bind_interface`), через который будут устанавливаться исходящие соединения с серверами (например, `eth3`, `nwg0`, `ppp0`). Это позволяет жёстко зафиксировать uplink для конкретных провайдеров или туннелей. При смене интерфейса в настройках URL-подписки параметры применяются к серверам сразу из локального состояния, без обращения к сети — переключиться на модем можно и при лежащем основном канале.

- **Два новых параметра маскировки AmneziaWG 3.1: случайные хвосты и отключение cookie.** Их приносит версия протокола 3.1, и настраиваются они в редакторе туннеля рядом с остальными параметрами обфускации. (проверить версию amnezia-linux-kernel-module необходимо через demsg | grep amnezia - ожидаемая версия **3.1.20260812**)

   Обе новые настройки показываются только там, где они действительно работают: в режиме ядра нужен загруженный модуль AmneziaWG версии не ниже 3.1. Обратной совместимости между 3.1 и 3.0 нет, так же как между 3.0 и 2.0.

**ВАЖНО**: Перезагрузите роутер после установки новой версии AWGM. Модуль ядра загружается только на старте системы и не может быть загружен на действующей системе автоматически.

  Для MIPSBE (en7512 и en7516) — это KN-2010, KN-2110, KN-2112, KN-2410, KN-2510 и KN-3610. На них режим ядра не работал в принципе, при любых настройках, теперь исправление пришло из upstream протокола.

- **Автозапуск служб Entware переключается из интерфейса.** На вкладке «Система → Службы» у каждой службы появился переключатель автозапуска: он переименовывает скрипт в `/opt/etc/init.d/` между `Sxx` (запускается при старте роутера) и `Kxx` (не запускается). Раньше отключить автозапуск можно было только вручную по SSH, и выключенные службы вообще не были видны — файлы с префиксом `K` в список не попадали. Автозапуск служб, на которых держится сам AWG Manager — `awg-manager`, `ttyd`, `sing-box`, `dropbear`, — выключить нельзя.

- **Раздел «Прокси» — отдельная страница вместо двух вкладок на главной.** Всё, что относится к выходу трафика роутера наружу и к раздаче этого выхода другим, собрано в одном месте: вкладка «Выход» и вкладка «Раздача». Слева — список инстансов обоих протоколов сразу, WDTT и FreeTurn вперемешку; справа — карточка выбранного: состояние процесса, куда идёт трафик, параметры, освобождение портов, журнал. Экспертные поля не спрятаны за глобальным режимом «Эксперт», а раскрываются секцией «Дополнительно» в самой карточке.

  Новый инстанс заводит мастер. «Вывести трафик» принимает выданную ссылку любого вида — WDTT, FreeTurn, подписку — сам разбирает её, спрашивает недостающее и в конце предлагает добавить готовый интерфейс в политику доступа роутера. «Настроить раздачу» ведёт от выбора протокола до готовой ссылки первому абоненту; протокол, который на этом роутере не поднимется, в мастере помечен и не предлагается.

  Абоненты WDTT-сервера получили собственный блок. Имя абонента можно менять, не трогая доступ. Доступ можно перевыпустить — абоненту выдаётся новый пароль с тем же именем, а старый снимается; это единственный способ вернуть в строй просроченного, продления в интерфейсе нет. Просроченный, отключённый и заведённый автоматически видны бейджами, и у каждого доступны только те кнопки, которые сервер действительно исполнит. Новый абонент заводится в отдельном окне — с именем и, где нужно, с VK-хешем.

  Главная страница теперь только про туннели: вкладки «FreeTurn» и «WDTT» и кнопки в тулбаре дашборда с неё убраны. Старые адреса `/wdtt`, `/freeturn` и ссылки вида `?tab=wdtt` работают по-прежнему — они приводят на новую страницу.

- **Трафик абонентов можно пустить по правилам sing-box — тумблером прямо в строке состояния раздачи.** Включено — абоненты ходят по тем же правилам маршрутизации, что и устройства сети; выключено — выходят напрямую, минуя их. Раньше это настраивалось в другом разделе и с раздачей никак не связывалось.

- **Переключатель «Использовать в политиках доступа» у сервера раздачи.** Пока он выключен, интерфейсы сервера остаются внутренними и роутер не предлагает их в политиках доступа. Значение применяется при запуске сервера: изменённое, но ещё не применённое, помечено рядом с переключателем — работающий сервер из-за него не перезапускается.

### Изменено

- **Имена интерфейсов в разделе «Прокси» показываются так же, как в веб-интерфейсе роутера** — `OpkgTun17` вместо `opkgtun17`, и уж тем более вместо `wdtt0`. Найти интерфейс в настройках роутера по тому, что написано у нас, теперь можно буквально поиском по строке. Внутренние имена никуда не делись — они остались в подсказках и в секции «Дополнительно», где действительно нужны.

- **Встроенный sing-box обновлён до 1.14.0-beta.17-awgm.13** — версия понимает оба новых параметра 3.1 для туннелей, работающих через sing-box, и приносит с собой три исправления.
### Изменено

  **Туннель с доменным адресом сервера больше не мешает запуску.** Если адрес VPN-сервера задан именем, а не IP, sing-box раньше отказывался стартовать, пока это имя не разрешится. После перезагрузки роутера DNS поднимается не мгновенно, поэтому движок падал, пробовал снова, снова падал — и уходил в паузу, которая доходила до пятнадцати минут. Всё это время туннели не работали, хотя интернет уже был. Теперь запуск не ждёт: имя разрешается позже, при первой попытке связаться с сервером, и туннель поднимается сам.

  **Подключения по REALITY к серверам со свежим Xray.** Xray начиная с версии 26.3.27 по умолчанию отклоняет клиентов, которые представляются версией старее его собственного порога, — под это попадали все сборки sing-box, включая нашу, и подключение просто не устанавливалось без внятной причины. Особенно заметно стало после панели 3x-ui 3.5.0, которая приносит с собой Xray 26.7.11. Версия, которую сообщает наш клиент, обновлена, и такие серверы снова принимают подключение.

  **Обновлён mieru — 3.36.0.** Сервер быстрее опознаёт пользователя при новых подключениях, а шифрование стало экономнее к памяти: меньше нагрузки на сборщик мусора, что заметнее всего на слабых моделях.

### Исправления

- **FakeIP: выбранный «настоящий» DNS-сервер снова участвует в резолве доменов.** В режиме FakeIP движок назначает резолвером доменных адресов свой отдельный сервер, но эта запись молча пропадала при склейке конфигурации: одноимённый ключ базового файла перекрывал её, потому что при совпадении скаляров sing-box берёт значение из файла, идущего первым по имени. В итоге домены резолвил bootstrap-резолвер, а адрес, выбранный в настройках FakeIP, не влиял ни на что.

  Теперь значения по умолчанию для таких «спорных» ключей вынесены в отдельный файл конфигурации, который читается последним. Любой режим маршрутизации перекрывает их просто тем, что задаёт своё, — а когда режим выключен, работает значение по умолчанию. Раньше базовому файлу приходилось уступать ключ активно, и он делал это дважды за одно переключение режима: сначала забирал, потом отдавал. Каждая такая правка перезапускала движок, а при поднятом туннеле перезапуск рвёт все соединения.

- **Переключение режима маршрутизации перезапускает движок один раз, а не два-три.** При включённом туннеле sing-box нельзя перенастроить на лету — его можно только остановить и запустить заново, и каждый такой перезапуск обрывает все соединения клиентов. Переключение режима успевало перезаписать конфигурацию несколько раз, и лишние перезапуски накладывались на момент, когда трафик клиентов уже направлен в туннель. Теперь за одно переключение движок перезапускается ровно один раз.

- **FakeIP не включался вовсе, если в настройках задан пул IPv6.** Маршрут для этого пула запрашивался у роутера в форме, которую тот не принимает: обязательное поле называется иначе, чем у обычных IPv4-маршрутов. Роутер отвечал невнятной ошибкой «no input», включение режима откатывалось, и FakeIP оставался недоступен — а пул IPv6 задан по умолчанию, так что затрагивало это всех. Та же ошибка в обратной операции целилась не в тот маршрут: без обязательного поля роутер понимал запрос как удаление маршрута по умолчанию.

- **Переключения режимов больше не исчерпывают пул сетевых интерфейсов.** Каждое включение туннельного режима занимает номер интерфейса `OpkgTun` из десяти доступных. При выключении номер должен освобождаться, но интерфейс переживал удаление, если в этот момент его держал работающий движок: роутер о нём забывал, а в системе он оставался и продолжал считаться занятым. Примерно после десяти переключений свободных номеров не оставалось, и маршрутизация переставала включаться с ошибкой «нет свободного OpkgTun-индекса». Отдельно нашлась и обратная беда: некоторые служебные команды создавали пустой интерфейс просто по обращению к его имени — в том числе при уборке за уже удалённым.

- **Туннель, отцепившийся от движка, теперь чинится сам.** Бывает состояние, когда sing-box работает и отвечает, режим числится включённым, а трафик клиентов уходит в никуда: сетевой стек движка отвязался от туннельного интерфейса. Ни одна из проверок этого не ловила — восстанавливал только ручной перезапуск. Теперь такое состояние распознаётся и лечится перезапуском движка, но не сразу: одиночный сбой связи пропускается (сразу после перезапуска интерфейс поднимается не мгновенно), а после трёх безуспешных попыток лечение прекращается — если перезапуск не помог, он не поможет и в десятый раз, а соединения рвёт каждый.

- **HydraRoute Neo: правила по подсетям снова работают (#767).** Правило с доменами (например, `2ip.io`) уезжало в туннель, а правило с подсетями — скажем, пресет Telegram — молча не срабатывало. Причина была не в самом правиле: сохранение настроек HR Neo в AWGM дописывало в конфигурацию демона наши значения по умолчанию, а они не совпадали с теми, что демон подставляет сам, когда ключа в файле нет. В файл уходило `CIDR=false`, и демон переставал читать список подсетей целиком; заодно писался `autoStart=false`, запрещавший ему запускаться после перезагрузки. Теперь наши значения совпадают с его собственными по всем параметрам, которыми мы управляем, а конфигурации, уже испорченные прежними версиями, чинятся при запуске — с записью в журнал и перезапуском демона, без ручного вмешательства. Значения, которые вы правили сами, при этом не трогаются.

- **Снятие маршрута по умолчанию больше не выглядит провалом.** Роутер отвечает на эту команду критической ошибкой `Io::Netlink … file exists`, хотя запись при этом реально снимает. С прошлого выпуска, где ответы роутера перестали теряться, эта ложная ошибка стала останавливать выключение режима «Политики + tun»: пользователю показывалась несуществующая неполадка, а внутренние кэши маршрутов не обновлялись.

- **Синхронизация DNS-маршрутов не застревает на удалённом интерфейсе.** Список на удаление строится из того, что сейчас на роутере, и мог содержать правило, чей интерфейс уже удалён. Отказ роутера на такой записи прерывал весь цикл синхронизации — вместе с последующими шагами, — и та самая запись не вычищалась уже никогда.

- **Сегмент, удалённый при включённом policy-tun, больше не ломает ни включение, ни выключение.** Восстанавливать NAT на исчезнувшем сегменте нечего: теперь он пропускается вместе со своей записью, а не роняет операцию целиком и не оставляет запись в настройках навсегда.

- **Частично применённые пакетные команды доезжают до сохранённой конфигурации.** Роутер применяет пакет поэлементно, поэтому отвергнутый элемент не отменяет остальные. Раньше при таком отказе сохранение не запрашивалось и внутренние кэши не сбрасывались — применённая половина терялась при перезагрузке, а следующая сверка считалась по устаревшим данным.

- **Режимы FakeIP и «Политики + tun» больше не предлагаются там, где они не работают (#768).** Оба построены на интерфейсе OpkgTun, а он появился только в KeeneticOS 5.x. На прошивках 4.x роутер отказывал в создании интерфейса, но отказ был не виден: включение доходило до следующего шага и падало сообщением про список доступа — «no "OpkgTun0" IP interface found», из которого понять причину было невозможно. Теперь на таких прошивках оба режима заблокированы с пояснением, а попытка включить их через API отклоняется до того, как разберётся текущий режим.

- **То же сделано и для остальных команд роутера.** Политики доступа и привязка устройств, прокси-интерфейсы, статические маршруты, NAT, DNS-маршруты, FQDN-группы и параметры маскировки AmneziaWG тоже читали только внешнюю оболочку ответа, поэтому, например, попытка добавить в политику устройство, не зарегистрированное на роутере, выглядела успешной и молча не срабатывала. Теперь такие отказы всплывают своим текстом. Повторный снос того, чего уже нет (политика, прокси, маршрут, правило DNS, группа), по-прежнему считается успехом — на этом держатся повторные попытки уборки.

- **Отказ роутера при настройке интерфейса больше не теряется.** Команды NDMS отвечают «200 OK» и кладут отказ внутрь ответа; создание интерфейса, назначение адреса, MTU, описания и подъём читали только внешнюю оболочку, поэтому проваленный шаг рапортовал об успехе, а падало через один-два шага и с чужой формулировкой. Теперь такие отказы всплывают сразу и своим текстом. Снос интерфейса, которого уже нет, по-прежнему считается успехом — на нём держатся повторные попытки уборки.

- **Подписки: серверы больше не объявляются сиротами на ровном месте.** После обновления подписки почти все её серверы попадали в «сироты» и тут же заводились заново — с тем же адресом, портом, SNI и именем (#745). На работу
  подписки это не влияло, но список сирот приходилось чистить руками после каждого обновления.

- **KeenDNS: все слмано**  Почему именно так: в прошивках 5.1.3 Preview и 5.2 Alpha адрес, по которому
  роутер обслуживает свои имена, переехал с `78.47.125.180` в диапазон `198.51.100.0/24` (у Keenetic и NetCraze он разный и может меняться). Такой адрес публичный DNS не отдаёт в принципе — попасть на роутер по имени можно только через его собственный резолвер. 


### Изменения работы (в т.ч. Breaking Changes)

- **Главный пароль WDTT-сервера больше не пускает в туннель — все ссылки, выданные на нём, перестают работать.** Раньше основным паролем сервера подключались все, и он же был ключом администрирования: одна строка одновременно открывала доступ и управляла сервером, поэтому уезжала в каждую выданную ссылку. Теперь сервер принимает только пароли абонентов, а главный пароль остаётся ключом администрирования и в ссылки не попадает.

  **Миграции нет, и это намеренно.** После обновления каждому, кто подключался по старой ссылке, нужно выдать новую — на его абонента. Абоненты, заведённые телеграм-ботом сервера, при первом же запуске подхватываются автоматически — с паролем, именем и сроком действия. Но прежняя версия собирала файл паролей заново при каждом старте сервера, поэтому те, кого бот завёл до последнего перезапуска, пропали ещё до обновления и не вернутся: их надо завести заново.

  Чтобы сервер не оказался мёртвым, при запуске без единого рабочего абонента awg-manager заводит «Абонент 1» сам: без единого пароля `wdtt-server` не стартует вообще. Это не перенос данных — это тот же исходный абонент, которого получает любой новый сервер.

- **Первый запуск после обновления сбрасывает привязки устройств.** Подключённые клиенты переподключатся и получат новые адреса из пула. Это разовая цена: прежняя версия обнуляла привязки при каждом старте сервера, то есть не хранила их вовсе; теперь они переживают перезапуск.

- **Срок действия абонента заработал по-настоящему.** Раньше он обнулялся при каждом старте сервера, и любой временный пароль, выданный телеграм-ботом, становился бессрочным. Теперь срок сохраняется: абонент, у которого он истёк, доступ не даёт, серверу не передаётся и ссылку на него выдать нельзя. Продления из интерфейса нет — чтобы вернуть доступ, удалите просроченного абонента и заведите нового; занять его пароль, не удалив запись, не получится.

- **Список абонентов живёт в настройках awg-manager, база `panel.db` больше не используется.** В 2.17.0 список уже переехал в настройки, чтобы абоненты не пропадали после сбойного чтения базы; теперь ушла и сама база — вместе со встроенным в awg-manager движком SQLite. Оставшийся на диске файл `panel.db` ни на что не влияет, удалить его можно руками. Файл с паролями, который читает сервер, пишется с правами `0600` — доступен только владельцу.

- **Добавление и удаление абонента применяются к запущенному серверу сразу.** До этого они не применялись вовсе: изменения доезжали в лучшем случае со следующим запуском сервера, а до него новый абонент подключиться не мог. Теперь сервер перечитывает список по сигналу — без перезапуска и без разрыва чужих сессий; у удалённого абонента доступ отзывается немедленно.

- **Состав абонентов задаёт awg-manager: удаление абонента через телеграм-бота сервера он отменяет.** Заведённого ботом абонента awg-manager, наоборот, подхватывает и запоминает у себя, а вот убранного — вернёт при следующей синхронизации: источник правды один, и это настройки awg-manager. Удалять абонентов нужно здесь. Удалить последнего рабочего абонента awg-manager не даст — без единого пароля сервер не запустится; сначала заведите нового.

- **«Абонент 1» больше не заводится сам, когда настройки сервера сохраняет человек.** Раньше сохранение настроек с заданным главным паролем молча создавало абонента, если ни одного рабочего не осталось: пароль был живой, ссылку по нему никто не выдавал, и в списке он появлялся ниоткуда. Теперь на путях интерфейса абонента за пользователя не заводит никто — состав списка меняют только явные действия.

  Взамен запуск сервера без единого рабочего абонента заблокирован в интерфейсе, с объяснением: без рабочего пароля `wdtt-server` не стартует вообще. Удаление последнего просроченного абонента поэтому больше не отменяется — оно осознанно оставляет сервер незапускаемым, пока не заведён новый. Страховка на пути запуска осталась на месте: если сервер поднимется мимо интерфейса — сторожем, автостартом или после обновления, — абонент по-прежнему будет заведён автоматически и помечен в списке соответствующим бейджем.

## [2.17.2] - 2026-08-12

### Исправления

- **Выключенный сервер WDTT больше не нагружает роутер круглые сутки** — уборщик брошенных интерфейсов считал сиротой любой интерфейс, чей процесс не запущен. Выключенный пользователем сервер под это подходит навсегда: раз в 15 секунд шла попытка снести его интерфейс, хотя сносить было нечего. Хуже того, обращение к несуществующему интерфейсу роутер трактует как просьбу его создать — уборка сама создавала интерфейс, чтобы тут же его удалить. Каждый такой круг — четыре команды роутеру, запись конфигурации во флеш-память, полный сброс кэшей и событие «интерфейс удалён», от которого интерфейс программы перезапрашивал весь список туннелей. В журнале это выглядело как полторы тысячи событий от интерфейса, которого в роутере нет, а команды к роутеру начинали обрываться по таймауту.

  Теперь уборка сначала спрашивает, существует ли интерфейс, и на пустом месте не делает ничего. Заодно перестал повторяться холостой снос правил NAT: пока ни один сервер не работает, он делается один раз, а не каждые 15 секунд — это около восемнадцати вызовов iptables на каждый круг. По той же причине перестала вхолостую работать и сверка правил для портов прокси-серверов: пока открывать нечего, восстанавливать тоже нечего.
- **Сверка портов прокси-серверов больше не считает своими чужие правила межсетевого экрана** — правила для этих портов ставились без пометки, по которой их можно узнать, и отличать свои приходилось по виду. Проверка была слишком широкой: под неё попадало любое разрешающее правило с указанием порта — в том числе правила самого роутера и других пакетов. Каждое такое правило программа считала своим и на каждом круге сверки пыталась убрать: впустую тратила вызовы iptables, а разрешение с тем же портом, но без уточнений, могла и правда снести.

  Теперь пометка ставится — нужный для неё модуль ядра программа при необходимости догружает сама, и на роутере он есть. Помеченное правило принадлежит нам однозначно. Там, где модуля нет вовсе, правило ставится без пометки, чтобы порт всё равно открылся; такие правила, как и оставшиеся от прошлых версий, признаются своими только по точному виду — любое уточнение (входящий интерфейс, адрес источника, дополнительное условие, диапазон портов) снимает признание. Ту же помеченную форму ставит и скрипт, восстанавливающий правила после перенастройки межсетевого экрана роутером.
- **Разрешение на пересылку трафика WDTT-сервера больше не остаётся в межсетевом экране навсегда** — правило, открывающее пересылку через интерфейс сервера, ставится в одной форме, а снимать его пытались в другой: с версии 2.17.0 они разошлись. Снятие поэтому не удаляло ничего, и после каждой остановки — да и удаления — сервера разрешение оставалось в межсетевом экране до перезагрузки роутера. Заметить это по интерфейсу было нельзя.

  Теперь форма правила одна на всех: и на постановку, и на проверку, и на снятие, и в скрипте, который восстанавливает правила после перенастройки межсетевого экрана роутером. Правила, оставшиеся от версий 2.17.0 и 2.17.1, снимаются при первой же уборке.
- **Морда роутера снова открывается по имени KeenDNS с устройств в политике** — пресет «KeenDNS / CrazeDNS» подставлял таким устройствам локальный адрес роутера вместо адреса, который роутер сам сообщает по этому имени своей статической записью. Адрес у сервиса общий и не случайный: по нему запрос попадает в нужный раздел веб-сервера. Подмена на локальный адрес отправляла браузер по кругу — переход по своему домену возвращал на него же, и админка не открывалась вовсе. С устройств вне политики всё работало, потому что им отвечает сам роутер, а не движок маршрутизации; из-за этого поломка выглядела необъяснимо.

  Теперь пресет зеркалит то, что роутер отдаёт сам, и заодно выводит этот адрес из перехвата — иначе запрос ушёл бы в туннель и упёрся бы в отказ соединения. Адрес читается с роутера, а не зашит в программу, и обновляется без перезапуска движка. Порталы `my.keenetic.net` и `my.netcraze.net` обрабатываются так же. Если KeenDNS работает в режиме прямого доступа, отдельной настройки не требуется: имя ведёт на внешний адрес самого роутера, а он из перехвата исключён всегда.
- **Обход по гео-меткам больше не пугает предупреждением о недоступном модуле ядра** — в настройках обхода показывалось, что модуль `xt_set` недоступен и правило обхода не встанет. Проверка искала его двумя способами: среди загруженных модулей и файлом на диске. На прошивках Keenetic он не является ни тем, ни другим — он встроен в само ядро, поэтому оба способа его не находят, хотя работает он безотказно. Предупреждение выводилось на полностью исправной конфигурации, ничего не блокировало и подсказать пользователю могло только неверное.

  Проверка удалена. Настоящая нехватка — если она где-то встретится — и раньше выяснялась не ею, а отказом при установке правил, с конкретным сообщением в журнале. Догрузка модуля на прошивках, где он всё же вынесен из ядра, осталась на месте.

## [2.17.0] - 2026-08-11

### Новые возможности

- **Режим маршрутизации «Политики + tun»** — третий способ завести трафик в sing-box, рядом с TPROXY-правилами и FakeIP. Роутер поднимает `OpkgTun`-интерфейс и регистрирует его в NDMS как обычный  с глобальным приоритетом и маршрутом по умолчанию (ipv4/v6), после чего интерфейс становится доступен для выбора в политиках доступа Keenetic. Кого пускать через sing-box, решаются в политиках доступа на вкладке «Политики доступа» или веб-интерфейс роутера,а не правила netfilter: перехвата TPROXY в этом режиме нет вовсе, как нет и подмены адресов FakeIP-пулом. Внутри sing-box работают те же правила, outbound'ы и итоговое действие, что и в TProxy: переключение между двумя режимами не теряет ни одного правила маршрутизации. (Общие правила маршрутизации и наборы rulesets, общие правила DNS резолвинга, отличие только в секции ingress)

  Выбор устройств для которых будет работать этот режим осуществляется через добавление в политику доступа с созданным OpkgTun интерфейсом; kill-switch получается сам собой, т.к. устройство в политике, где разрешён только этот интерфейс, при остановленном sing-box остаётся без сети. Тумблер «Маршрутизация через sing-box» на карточках WireGuard- и WDTT-серверов работает и здесь: трафик их клиентов уходит в туннель отдельной таблицей маршрутизации, а их DNS-запросы перенаправляются на резолвер туннеля. Главный вопрос «включил, а трафика нет» разбирается без журнала: если интерфейс не разрешён ни в одной политике, карточка режима говорит об этом прямо и показывает, под каким именем интерфейс виден в политиках.

  **Важно знать**: доменные правила работают по подсмотренному имени (SNI/Host), поэтому трафик, где имя не видно, а именно ECH (Ecnrypted Client Hello), не-HTTP-протоколы, маршрутизируется по IP-адресу; **ping (ICMP) клиентов через туннель не проходит** и на слабых процессорах растёт нагрузка (стек userspace у singbox, в настоящее время единственными кандидатами для использования режима являются ARM роутеры не ниже 3811/3812 и их кинетикозаменители); перехват DNS работает по 53-му порту, поэтому клиент с собственным шифрованным DNS (DoH/DoT) резолвит мимо туннеля.

- **«Политики + tun»: интерфейс разрешается в политике сам, а его номер переживает выключение** — раньше режим создавал `OpkgTun<N>`, но разрешить его выходом политики доступа приходилось руками, иначе трафик в туннель просто не заходил. Теперь разрешение ставится автоматически в выбранную политику и первым в списке выходов — туннель становится для её устройств выходом по умолчанию. Политика выбирается там же, в карточке режима; поле общее с режимом TPROXY. Замечание «интерфейс не разрешён» теперь смотрит именно на выбранную политику, а не на любую: разрешение, поставленное когда-то другой политике, больше не выдаётся за рабочую настройку.

  Выключение режима больше не удаляет интерфейс, а кладёт его и снимает адреса. Номер за режимом закрепляется, и следующее включение берёт тот же — а значит, разрешение в политике, привязанное к имени, не ломается. Интерфейс убирается там, где он действительно не нужен: при переключении на другой режим маршрутизации и при удалении пакета (вместе с маршрутом по умолчанию и возвратом исходного NAT сегментов).

  Чего продукт не делает: если номер всё-таки сменился (номер занял чужой интерфейс, пока запись была потеряна), старое разрешение остаётся в политике — снимать его автоматически мы не беремся, потому что под руку попало бы разрешение, выданное вручную и осознанно. Журнал в этом случае предупреждает, что номер сменился, и называет интерфейс, к которому запись относится. Неудачное включение при откате удаляет интерфейс, даже если он существовал до попытки, — разрешение в политике после такого стоит проверить.

- **QoS-классы работают и в режиме «Политики + tun»** — sing-box не умеет разбирать DSCP-метку, поэтому классификация остаётся на netfilter, но набор правил урезан до необходимого: исключения (локальные сети, мультикаст, пользовательские bypass по адресам и портам) и правила по самой метке, без общего перехвата всего UDP и TCP и без blackhole-правила — fail-closed здесь обеспечивает политика. Пока активных классов нет, netfilter в этом режиме не трогается вообще.

- **«Сохранять адреса клиентов»** — по умолчанию sing-box видит все устройства под одним адресом tun-шлюза (`172.18.0.1`): маскарад роутера срабатывает раньше, чем трафик доходит до нас, — отсюда ни статистики по клиентам, ни правил по адресу источника. Опция переводит выбранные сегменты локальной сети на static-NAT, при котором трансляция делается только на выходе в интернет, и адреса клиентов доезжают до sing-box настоящими. Перед включением показывается список сегментов с их текущим режимом NAT — сегменты на динамическом NAT предвыбраны, лишние можно снять.

  Исходный режим NAT каждого сегмента записывается и возвращается как был — при выключении опции, снятии режима и переключении на другой, — а не подменяется на «динамический» вслепую: сегмент, который держали на static-NAT или вовсе без NAT намеренно, останется таким же. Опция меняет NAT-режим сегмента, поэтому её стоит проверять вместе с пробросом портов и UPnP. Включение вступает в силу со следующего подъёма режима, выключение применяется сразу.

- **Обход по geoip в исключениях TPROXY** — в исключениях перехвата можно отметить geoip-теги из подключённых гео-данных: подсети выбранных тегов уходят в WAN мимо sing-box прямо на уровне netfilter, не доходя до движка. Наполнение локальное — из тех же `.dat`-файлов, что использует маршрутизация, без запросов наружу и без ожидания резолва. Набор адресов (ipset `AWGM-BYPASS`) переживает и перестройку firewall роутером, и перезагрузку: он сохраняется на диск и восстанавливается тем же хуком, что возвращает наши цепочки. Рядом с выбором показан суммарный размер и предел набора — выбор больше предела не сохраняется.

  Обход полный, как у «Доп. подсетей»: под него попадает и DNS, поэтому клиент с DNS-сервером из выбранных диапазонов выпадает из DNS-перехвата вместе со всем, что от него зависит. Изменения действуют на новые соединения; уже установленные без пакета `conntrack-tools` доживут по прежнему пути до таймаута. Нужен пакет `ipset` — поставить его можно кнопкой рядом, как и `conntrack-tools`. В режиме «Политики + tun» раздела нет: правил перехвата там не ставится вовсе.

- **FreeTurn/WDTT: серверы поднимаются сами после перезагрузки** — флаг «должен работать» теперь сохраняется и для серверов, а не только для клиентов: запуск сервера ставит его, ручная остановка снимает. На загрузке роутера все инстансы с этим флагом стартуют автоматически, там же, где и раньше стартовали клиенты — после готовности NDMS/WAN и DNS.

  Если сервер FreeTurn когда-то сохранялся с включённым флагом в старом конфиге, после обновления он поднимется на первой же загрузке. Чтобы этого не происходило, остановите его кнопкой — ручная остановка флаг снимает.

- **Watchdog для прокси-процессов** — раз в 30 секунд проверяется, жив ли процесс каждого включённого клиента и сервера FreeTurn/WDTT; упавший поднимается заново. Остановленные пользователем инстансы не воскресают. Неудачные попытки старта разводятся по времени (30 с, минута, две… до 15 минут), поэтому сломанный конфиг или занятый порт не превращаются в бесконечный цикл перезапусков с NDMS-вызовами и потоком записей в журнал.

- **Перезапуск клиента без живого пира** — если у запущенного клиента нет ни одной активной сессии несколько проверок подряд, он перезапускается: так лечится «висящий» клиент, потерявший связь с сервером. Ожидание после старта — 3 минуты у FreeTurn и 5 у WDTT (там дольше идёт VK-авторизация), ожидание капчи у FreeTurn перезапуск откладывает. Когда клиент вообще не сообщает статистику, состояние считается неизвестным и перезапуска не происходит — иначе под нож попадал бы исправно работающий туннель.

- **WDTT: режим Raw** — клиент и сервер могут работать без WireGuard: трафик идёт напрямую через `wt-client`, AWG-туннель не создаётся и WG-порт на сервере не используется. Режим требует бинарей с его поддержкой (на стороне сервера — редеплой); со старыми бинарями запуск завершится ошибкой о неизвестном флаге, а сам режим по умолчанию — прежний, WG.

- **Кнопка «освободить порт»** — рядом с listen-адресом инстанса показывается PID и имя процесса, занявшего порт, и его можно остановить, не заходя по SSH. Остановить разрешено только процесс на порту, который прописан в настройках инстанса FreeTurn/WDTT; чужие порты (RCI, DNS, SSH роутера) ручка отклоняет.

- **Синхронизация endpoint связанных AWG-туннелей** — при смене listen-порта клиента `Endpoint` связанного туннеля обновляется автоматически. Порт клиента переназначается сам, когда прежний занят — после перезагрузки роутера это случается регулярно, — и раньше туннель оставался настроенным на старый порт: связка молча переставала работать до ручной правки. Теперь новый адрес доезжает и до работающего туннеля, и до карточки в интерфейсе, а не только до файла настроек. Сохранение настроек клиента сверяет endpoint так же, как это делал запуск.

- **WDTT: адреса для режимов WG и Raw хранятся раздельно** — у режимов разные порты сервера, и раньше переключение затирало адрес соседнего: вернувшись обратно, приходилось вводить его заново. Теперь каждый режим помнит свой адрес, а в экспертном виде оба видны сразу. Если адрес для нужного режима ещё не вводили, поле остаётся пустым — вместо молчаливой попытки подключиться на порт другого режима.

- **Баннер-дисклеймер ограничений NDMS-маршрутизации** — на вкладке «Маршрутизация → NDMS» перед списком правил теперь показывается баннер с шестью ограничениями встроенного DNS-движка NDMS: работа только в «Политике по умолчанию», обход через собственный DoH/DoT на устройстве или в браузере, гонка первого запроса с попаданием адреса в таблицу маршрутизации, совпадение по суффиксу домена, короткий TTL и стороннее ПО в Entware, перехватывающее DNS-запросы. Ссылки под списком ведут на две профильные темы форума Keenetic.

  Кнопка «Я прочитал — проверить себя» открывает мини-квиз из трёх вопросов с одним вариантом ответа; неверный ответ подсвечивается и объясняется, а вопрос остаётся открытым до правильного. После трёх верных ответов баннер схлопывается в строку «Ограничения NDMS-маршрутизации приняты» со ссылкой «Показать», которая разворачивает список обратно. Виден баннер только на OS5, где и существует сам движок NDMS-маршрутизации.

  **Особенности**: подтверждение хранится в localStorage браузера, а не на роутере — на другом устройстве или после очистки данных сайта баннер и квиз появятся снова. Прохождение квиза ничего не блокирует: правила DNS-маршрутизации создаются и без подтверждения, оно работает как памятка, а не как гейт.

### Исправления

- **Правило «готовый набор + свои домены и подсети» снова работает** — если к правилу из каталога (Discord, Telegram, Roblox, WhatsApp) дописать собственные подсети или домены, правило переставало ловить хоть что-нибудь: sing-box требует совпадения И по набору, И по вашему списку одновременно, а не по любому из них. Со стороны это выглядело как «правило исчезло»: инспектор маршрутов показывал «не подходит» и для домена из набора, и для адреса из вашей подсети, а трафик уходил напрямую. Помогало только убрать свои адреса из правила или завести их отдельным правилом без пресета.

  Теперь такое правило сохраняется в форме «набор **или** ваши адреса» — срабатывает любая из сторон, как и ожидается от одной строки с обоими списками. Правила, уже сохранённые в сломанном виде, чинятся сами при первом запуске обновлённого пакета; редактировать их вручную не нужно. Сужающие условия (порт, протокол, TCP/UDP, адрес источника) по-прежнему обязательны — они ограничивают правило целиком, а не одну его сторону.

  Затронуты были не все пресеты: правило ломалось с наборами, внутри которых больше одного условия. У остальных (YouTube, Netflix, OpenAI, X и прочих) сочетание с собственными адресами работало и раньше — sing-box сливает такой набор с правилом сам.

- **Инспектор маршрутов больше не объявляет рабочее правило нерабочим** — он проверял все условия правила «через И», тогда как sing-box объединяет домены и подсети одного правила «через ИЛИ». Правило со списком доменов и списком подсетей сразу инспектор считал несовпавшим для любого запроса, хотя движок его исполнял. Заодно инспектор научился точным доменам (`domain`) — раньше правило с одним таким условием он считал пустым и молча пропускал — и логическим правилам, которые до сих пор не разбирал вовсе.

- **Инспектор учитывает ограничение по TCP/UDP** — условие «Сеть (L4)» в правиле он не смотрел вовсе, поэтому правило «только UDP» отчитывалось совпадением и для TCP-проверки. Теперь выбранный в проверке протокол сверяется именно с этим условием. Условия, которых при ручной проверке взяться неоткуда — прикладной протокол (его определяет сниффер) и привязка ко входу, — больше не выдаются за совпадение и честно помечаются как непроверяемые: правило с ними показывается несовпавшим, а не «подходящим наугад».

- **Принудительное удаление набора больше не превращает правило в «пропустить всё через туннель»** — если у правила удаляемый набор был единственным условием (обычное «пресет → туннель»), после удаления оно оставалось вообще без условий. Правило без условий sing-box считает подходящим для **любого** соединения, так что весь трафик роутера молча уходил в указанный туннель. Теперь такое правило удаляется вместе с последним своим условием — и в маршрутизации, и в DNS-правилах. Правила, не ссылавшиеся на удаляемый набор, не трогаются.

- **Редактор правила больше не теряет то, чего не показывает** — правило пересобиралось из полей формы, поэтому сохранение выбрасывало всё, для чего в форме нет поля: точные домены, прикладной протокол, признак локальной сети, привязку ко входу. Достаточно было открыть импортированное правило и нажать «Сохранить», ничего не меняя. Теперь такие условия переносятся как есть.

- **Ручной редактор конфигурации предупреждает о правиле, которое не сработает** — если в слоте эксперта записано правило с готовым набором и собственными адресами сразу, проверка и применение теперь возвращают замечание с номером правила. Сам текст слота не переписывается: он ваш, и правки в нём остаются вашими.

- **«Политики + tun»: DNS-запросы клиентов больше не уходят мимо туннеля** — в этом режиме трафик заворачивает сама политика доступа роутера, то есть уже после того, как принято решение о маршрутизации, а DNS-запрос клиент адресует самому роутеру — до туннеля он не доходил вовсе. Со стороны это выглядело как «правила по доменам работают вполсилы»: имя резолвил обычный резолвер роутера, и в туннель уходил уже готовый адрес, о котором правило ничего не знает. Теперь запросы на 53-й порт от устройств политики перенаправляются на резолвер туннеля; то же включено и клиентам серверов, у которых поднят тумблер «Маршрутизация через sing-box».

  Перехват держится собственным хуком (`52-awgm-policytun-dns.sh`) и восстанавливается после того, как роутер перестраивает свой firewall. Хук намеренно работает без проверки «жив ли sing-box»: когда движка нет, у членов политики не работает и весь остальной трафик, поэтому чинить в одиночку один DNS незачем. Перехват идёт по 53-му порту — клиент с собственным шифрованным DNS (DoH/DoT) по-прежнему резолвит мимо.

- **«Маршрутизация через sing-box» у сервера теперь работает и в режиме FakeIP** — переключатель на карточке WDTT- и WireGuard-сервера сохраняет интерфейс в списке захвата, но пользовался этим списком только режим tproxy: он помечает трафик интерфейса меткой политики. В FakeIP правил netfilter не ставится вовсе, поэтому переключатель не делал ничего. Со стороны это выглядело как «работает наполовину»: маршрутизация по IP-адресам у клиентов таких серверов шла — адреса из правил движка разложены статическими маршрутами в туннель для всего роутера, — а по доменам нет: DNS-запросы клиентов уходили мимо резолвера FakeIP, и домен превращался в настоящий адрес ещё до того, как правило могло сработать.

  Теперь в FakeIP переключатель делает то же, что и в tproxy. DNS-запросы клиентов перенаправляются на резолвер туннеля независимо от того, какой сервер прописан у них в конфигурации, включая адрес самого роутера. Остальной трафик уходит в туннель отдельной таблицей маршрутизации, и решение принимают правила движка, а не глобальные маршруты; обращения в локальную сеть роутера из заворота исключены, поэтому «Доступ в LAN» у сервера работает как прежде. Правила восстанавливаются сами после того, как роутер перестраивает свой firewall, и снимаются при выключении режима, смене состава серверов и удалении сервера.

  Цена включения описана прямо у переключателя: весь трафик клиентов идёт через sing-box, отчего растёт нагрузка на процессор, ping (ICMP) через туннель не проходит, а при остановленном sing-box клиенты остаются без сети. Перехват работает по 53-му порту — клиент с собственным шифрованным DNS (DoH/DoT) по-прежнему резолвит мимо; IPv6-трафик не заворачивается.

- **Правила «VPN для устройств» видны в окружении диагностики** ([#663](https://github.com/hoaxisr/awg-manager/issues/663)) — на странице «О системе» строка «VPN для устройств» показывала на самом деле прокси SOCKS5/HTTP: это разные подсистемы, а имя у строки было от вкладки с правилами. Сколько правил заведено и сколько из них включено, не показывалось нигде. Теперь это две отдельные строки — «Прокси для устройств» и «VPN для устройств» со счётчиком «включено / всего».

- **Туннель Keenetic с доменным адресом сервера возвращается к жизни сам** ([#702](https://github.com/hoaxisr/awg-manager/issues/702)) — после смены адреса за именем (DDNS, переезд сервера) туннель ложился навсегда: карточка бесконечно показывала «Запуск...», встроенный мониторинг раз за разом перезапускал интерфейс, а счётчик перезапусков при этом стоял на нуле. Причин было три, и чинятся они по отдельности.

  Первая: в конфигурацию роутера, уходило само доменное имя. Роутер резолвит его сам и при неудаче молча не поднимает интерфейс и ни строки в его журнале,а однажды разрезолвленный адрес больше не обновляет. Теперь AWG-M передает адрес, а не доменное имя, и следит за ним: как только адрес за доменным именем меняется, новый доводится туда, где он реально работает, в конфигурацию роутера на прошивках с нативным WireGuard ASC 2.0 и в слот прокси-модуля на остальных. Слежение переживает перезапуск AWG-M и не трогает остановленные туннели. Адрес IPv6 роутер в конфигурации не принимает вовсе, поэтому там стоит заглушка, а настоящий адрес выставляется при запуске через **wg** утилиту Entware; на старом прокси-модуле без поддержки IPv6 живой туннель ради заведомо неудачной пересборки больше не роняется.

  Вторая: состояние «интерфейс поднят, но пира нет» считалось запуском без ограничения по времени. Теперь через пять минут в таком виде туннель честно показывается сломанным и на карточке, и в мониторинге; замена конфигурации сломанного туннеля снова его перезапускает.

  Третья: перезапуски интерфейса силами роутера не считались (уходила константа) и не были видны на карточке туннеля. Теперь счётчик настоящий, показывается в подсказке «Восстановление (N)» и не обнуляется от самих перезапусков.

  Сверх этого: если три перезапуска подряд не дали ни одной удачной проверки, туннель перезапускается целиком — так же, как это делается кнопкой, но не чаще раза в 15 минут. Полный перезапуск подчиняется настройке «Перезапуск при dead»: выключена — ничего не трогаем.

- **FreeTurn/WDTT: автостарт переживает и обновление пакета, и перезагрузку роутера** — до сих пор он ломался в трёх местах сразу. Сохранение настроек гасило флаг «должен работать»: форма присылает конфиг целиком вместе со снятой галкой, прочитанной ещё до запуска, — теперь флаг ставится и снимается только кнопками «Запустить»/«Остановить», а сохранение настроек его не трогает. После `opkg upgrade` клиенты и серверы продолжают работать, но новый демон их уже не видит: журнала процесса нет, статистика не читается, watchdog слеп — такие процессы теперь перезапускаются, чтобы вернуться под надзор (ценой короткого разрыва трафика на обновлении). И наконец, pid-файл лежит на флешке и переживает перезагрузку, а после неё тот же номер процесса достаётся кому угодно: раньше это выглядело как «прокси уже запущен» и автостарт молча не срабатывал. Теперь номер сверяется с именем процесса в `/proc`, чужой процесс не считается нашим и — что важнее — не получает от нас сигнала остановки.

  Сам автостарт на обновлении демона теперь отложен так же, как на холодной загрузке (пауза и повтор), а не выполняется мгновенно: DNS и туннели к этому моменту могут быть ещё не готовы.

- **WDTT: клиент поднимается сам после перезапуска сервера** — с той стороны сессии обрываются, но клиент этого не замечает: воркеры числятся активными, наверх продолжают уходить keepalive-пакеты, а снизу не приходит ни байта. Такое состояние само не лечится — только перезапуском клиента. Теперь оно распознаётся, но осторожно: живой, но простаивающий туннель выглядит точно так же, поэтому перезапуск происходит, лишь если входящего трафика нет около десяти минут подряд.

- **TProxy: UDP-инбаунд больше не зацикливает сам себя** ([#689](https://github.com/hoaxisr/awg-manager/issues/689)) — `tproxy-in` слушал на `0.0.0.0`, хотя правила TPROXY направляют пакеты строго на `127.0.0.1`. Открытый на всех адресах сокет принимал и обычные UDP-пакеты, адресованные роутеру на этот порт; sing-box считал такой пакет перехваченным и честно пересылал «получателю» — то есть самому себе. Один случайный пакет заводил самоподдерживающуюся лавину: тысячи UDP-потоков `dst=<WAN>`, разбухший conntrack, процессор на 90-100% в обработке пакетов и обрывы TCP у устройств в политике. Теперь `tproxy-in` и tproxy-инбаунды QoS-классов слушают на `127.0.0.1` — перехваченный трафик доставляется как и раньше, а посторонние пакеты до сокета не доходят. `redirect-in` остаётся на `0.0.0.0`: NAT REDIRECT переписывает адрес назначения на адрес интерфейса, и loopback-листенер его бы не увидел. Диагноз до строки кода и проверка обхода на NC-1812 — [vanomilah](https://github.com/vanomilah).

- **TProxy: перестройка netfilter больше не убивает уже идущие UDP-потоки** ([#684](https://github.com/hoaxisr/awg-manager/issues/684)) — продолжение [#627](https://github.com/hoaxisr/awg-manager/issues/627). Тот фикс закрыл потоки, рождённые в окне без перехвата: они получали прямой NAT в WAN, и `awgm-ctclean.sh` выселяет их из conntrack. Но поток, живший до перестройки, NAT не имеет — он был перехвачен tproxy, — и под выселение не попадал. На время окна такой поток уходит из-под перехвата, и его подхватывает аппаратный движок PPE как обычный форвард: дальше пакеты коммутируются железом и в netfilter не входят вообще. Ни восстановление правил, ни удаление записи из conntrack не помогают — таблица PPE своя, и она же продолжает обновлять счётчики conntrack, поэтому запись не протухает. Со стороны это снова «меня перестали слышать до конца разговора»: клиент шлёт, ответов ноль, при этом TCP и новые UDP-потоки через тот же туннель работают.

  Теперь после возврата перехвата сбрасывается таблица аппаратного offload — каждый offload-поток один раз идёт медленным путём и переучивается уже через tproxy. Сброс делается там же, где выселение из conntrack: в netfilter.d-хуке после восстановления цепочек, при установке правил на старте движка и при самолечении. Только когда джамп перехвата реально на месте — сброс при отсутствующем джампе просто отправил бы те же потоки в offload заново. На платформах без узла `/proc/sys/net/hwnat/ppe_flush` шаг пропускается. Диагноз, измерения и вариант фикса — [tomas1pit](https://github.com/tomas1pit): на NC-1812 у мёртвого потока счётчик conntrack прошёл 8444 пакета при нулевых счётчиках правил mangle, а после сброса PPE поток ожил в ту же секунду; проверка фикса — 8 перестроек netfilter за две минуты без единого разрыва.

- **Исключение KeenDNS/CrazeDNS больше не уводит на роутер чужие адреса** — пресет исключал из перехвата адрес `78.47.125.180`, и домены Keenetic снова открывались локально. Но этот адрес общий: на него указывают A-записи *всех* KeenDNS-имён, а не только своих. Любое обращение к чужому `*.keenetic.pro` или `*.netcraze.pro` с устройства в политике попадало не к его владельцу, а на веб-интерфейс собственного роутера. **Важно**: В прошивках 5.2 Альфа сменили адрес который применялся годами, поведение будет неожидаемым, т.е. эта настройка не будет работать. Какое будет финальное решение разработчиков неизвестно. Использовать 5.2 Альфа на рабочем устройстве не рекомендуется.

  Теперь пресет работает иначе: имя роутера берётся из настроек KeenDNS в NDMS, и sing-box отвечает на запросы этого имени, его поддоменов и порталов локального доступа `my.keenetic.net` / `my.netcraze.net` адресом роутера в локальной сети — ровно так же, как это делает собственный DNS-сервер роутера. Чужие имена резолвятся как обычно. Записи видны в списке DNS-перезаписей с пометкой владельца; править и переносить их вручную нельзя, снимаются они выключением пресета. Если KeenDNS не забронирован, записей не появляется и в журнал пишется предупреждение; при временной недоступности NDMS или пропавшем адресе локальной сети прежние записи сохраняются, а не сбрасываются.

  Цена перехода: решение работает через DNS, поэтому клиент со своим шифрованным резолвером (DoH/DoT в браузере, Private DNS в Android) или с уже закэшированным ответом резолвит имя мимо роутера и по-прежнему уходит в туннель — прежнее исключение по адресу работало независимо от способа резолва. В ответе отдаётся адрес роутера в основном сегменте (`br0`): клиентам из других перехватываемых сегментов он может быть недоступен по правилам межсегментного доступа.

- **Клиенты WDTT-сервера больше не пропадают из списка** — заведённые в разделе «Раздача» клиенты жили только в `panel.db`, базе, которую пишет и сам `wdtt-server`. На старте он читает её целиком в память, а затем записывает обратно полной перезаписью таблицы. Если чтение по какой-то причине не удавалось — оборванный журнал SQLite после потери питания, занятый на тот момент файл, — сервер поднимался с пустой базой в памяти и тут же сохранял её на диск. Все клиенты с отдельными паролями исчезали навсегда, оставался только основной пароль сервера — тот, которым подключение продолжало работать.

  Теперь список клиентов хранится в настройках awg-manager и оттуда же восстанавливается: перед каждым запуском сервера `panel.db` пересобирается по нему, а строки, заведённые мимо awg-manager, наоборот подхватываются в настройки, а не теряются. Если база не читается, список всё равно показывается — с пометкой, что данные взяты из настроек и попадут в базу при следующем запуске. Сам `wdtt-server` пересобран: после неудачного чтения он больше не переписывает `panel.db` тем, что не смог прочитать.

- **Смена пароля WDTT-сервера отзывает прежний** — старый пароль оставался в `panel.db` отдельной строкой и продолжал пускать клиентов, пока его не удалишь вручную; сам `wdtt-server` эту строку не убирает. Теперь при смене пароля она снимается вместе с привязанными к ней устройствами.

- **Основной пароль сервера виден в списке клиентов, а его ссылка восстановима** — список показывал только клиентов с отдельными паролями, поэтому основной пароль, которым по умолчанию подключаются все, не был представлен вообще ничем. Ссылка `wdtt://` для него жила ровно до перезагрузки страницы: адрес и VK-хеши нигде не сохранялись, и собрать ту же ссылку заново можно было только по памяти. Теперь основной пароль — первая строка списка со своей кнопкой «Ссылка» и без кнопки удаления, а адрес и VK-хеши последней ссылки сохраняются в настройках сервера.

- WDTT-сервер: клиенты подчиняются маршрутизации роутера (HR, политики,sing-box). Сеть OpkgTun приведена к пулу клиентов (10.66.0.1/16), SNAT работает на любом egress (не только WAN), DNS клиентов заворачивается на роутер, правила переживают перезапись netfilter NDM. (#697)

- **Мёртвые процессы wdtt/freeturn больше не висят зомби** — надзор ждал, пока дочитаются логи процесса, и если выживший хелпер держал их открытыми, умерший процесс не хоронился, а супервизор считал его работающим и не перезапускал. Теперь процесс хоронится сразу по смерти, выжившие члены его группы добиваются, а утечка дескрипторов на каждом старте закрыта. (#697)

- **Автовосстановление wdtt/freeturn не устраивает штормов** — повторные попытки лечения (пересоздание интерфейса, рестарты по health-пробам и застою трафика) теперь затухают экспоненциально вместо бесконечного цикла каждые полминуты; ручное сохранение конфига снимает паузу немедленно. Заодно: усыновление живого процесса после рестарта демона больше не пересоздаёт интерфейс впустую, а MTU клиента переживает восстановление (раньше жёстко ставился 1300). (#697)

- **Страница перестала «залипать» при прокрутке на мобильном** ([#701](https://github.com/hoaxisr/awg-manager/issues/701)) — прокручивалась не сама страница, а её содержимое внутри блока высотой ровно в экран. Мобильный Chrome прячет адресную строку и обрабатывает прокрутку за край только для настоящей прокрутки страницы, поэтому после докрутки вниз и обратно вверх интерфейс обрывался на середине карточки: снизу оставалась пустая полоса, сверху часть страницы закрывала адресная строка. Заметнее всего это было в «Настройках» как самой длинной странице, но касалось всех. Теперь прокручивается страница целиком; защита от горизонтального сползания, ради которой всё и было заведено, сохранена.

- **Роутеры с ARM-процессором больше не перезагружаются раз в несколько часов при IPsec рядом с AWG-туннелем** — модуль шифрует пачку пакетов за один заход, занимая на это время блок ускорения NEON, и внутри этого захода уступал процессор другим задачам. На прошивке Keenetic такая уступка приводит к тому, что задача засыпает, оставив NEON помеченным как занятый: следующий, кто попробует им воспользоваться, падает вместе с ядром. Жертвой оказывалось шифрование IPsec — оно уходит на тот же блок и занимает его безусловно. Отсюда и картина, по которой дефект невозможно было связать с AWG: в отчёте о крахе видно только IPsec, а сам AWG-туннель при этом работает.

  Теперь NEON освобождается перед уступкой процессора и берётся обратно после — заснуть с занятым блоком стало нельзя. Проявлялось только на моделях с ARM (MT7622/MT7981/MT7988), только при одновременной нагрузке на IPsec и AWG, и не встречается в штатном WireGuard-модуле роутера, который такой уступки внутри работы с NEON не делает. Дефект есть и в исходном AmneziaWG. Два роутера с постоянным IPsec-туннелем рядом с нагруженным AWG перезагружались каждые 5-6 часов; с исправлением они отработали 48 часов без единого краха.

  Отдельная благодарность Nikolai Gridnev (@user241215) — за issue о перезагрузках и за пять дней самоотверженного тестирования: сборка за сборкой на боевых роутерах, со снятием отчётов о каждом крахе. Дефект воспроизводился раз в несколько часов и только под настоящей нагрузкой, поэтому без этого терпения найти его было нельзя.

  Модули пересобраны из тега `v3.0.20260805` с этим исправлением; в самом теге его нет. Сам тег приносит ещё одно: keepalive-пакеты определялись по нулевой длине, поэтому при включённом `ContentPaddingAddition` переставали быть пустыми и отбрасывались — на туннеле без полезного трафика это выглядело как «связь есть, а счётчики стоят». Обновлённый модуль загружается после перезагрузки роутера — до неё ядро продолжает работать со старым.

- **Kernel-режим заработал на KN-2010, KN-2110, KN-2112, KN-2410, KN-2510 и KN-3610** — на этих моделях туннель в режиме ядра не поднимался вообще. Модуль сверял тип входящего пакета, не переставив байты в порядок процессора, а у этих моделей он обратный остальным: мимо проверки проходили все четыре типа сообщений, включая рукопожатие, и роутер молча отбрасывал всё, что присылал сервер. Происходило это при любых настройках, а не только при своих значениях H1-H4, так что режим был неработоспособен целиком. Дефект есть и в исходном AmneziaWG — он исправлен в ветке 3.1, ещё не влитой в основную. Модули для этих моделей пересобраны с исправлением; на остальных перестановка байтов ничего не меняет, и их модули не трогали. NativeWG на этих роутерах работал и до исправления — поэтому дыра так долго не всплывала. Обновлённый модуль применяется после перезагрузки роутера.

### Изменения работы (в т.ч. Breaking Changes)

- **Селективный перехват убран** — идея была заворачивать в sing-box только адреса, стоящие за доменами из правил маршрутизации, а всё остальное отправлять прямо в WAN. Адреса для этого роутер добывал сам, резолвя домены правил со своей стороны, и перехватывалось только то, что попало в набор. В поле набор оставался пустым, то есть перехватывать было нечего, — механизм убран целиком вместе со своим ipset, слотом конфигурации и API. Настройка `selectiveBypass` в старых `settings.json` игнорируется, оставшиеся от неё артефакты снимаются при первом запуске.

  **Поведение после обновления меняется.** У тех, кто держал селектив включённым, через sing-box пойдёт весь трафик политики, а не почти ничего, как это было при пустом наборе. Стоит заранее посмотреть на нагрузку процессора и на правила маршрутизации: то, что раньше уходило мимо движка само собой, теперь решается его правилами. Точечно вывести адреса из перехвата можно «Доп. подсетями», а большие диапазоны — обходом по geoip.

- **sing-box обновлён до 1.14.0-beta.14-awgm.10** — сборка форка перенесена на upstream `v1.14.0-beta.14`. Из апстрима: клиент AnyTLS больше не отправляет серверу метаданные о себе (открытый сервер их не использует, но по ним профилировали пользователей), при необходимости их можно задать вручную. Дальше по бетам шли только исправления — заметных для нас четыре: QUIC-клиенты (hysteria2, TUIC, xhttp поверх HTTP/3) перешли на привязанный сокет и больше не рвут соединение, когда буфер отправки переполнен; DNS-кеш перестал сбрасываться при сбросе сети; починен размер буфера DNS-ответа.

  Наши AmneziaWG/AWG3 и mieru перенесены без изменений. В xhttp пришлось подогнать вызов под новый интерфейс QUIC-клиента и заодно закрыть утечку: под HTTP/3 UDP-сокет оставался открытым и при неудачном подключении, и после закрытия соединения.

- **Туннель к серверу по доменному имени переживает смену его адреса** — раньше домен разрешался один раз, при создании туннеля, и выбранный адрес оставался единственным до перезапуска sing-box: сервер за динамическим DNS после переезда становился недостижим, а из нескольких адресов в ответе использовался только первый — если он не отвечал, туннель не поднимался. Теперь имя разрешается заново на каждой попытке хендшейка, попытка уходит сразу на все полученные адреса, и туннель закрепляется за тем, откуда пришёл ответ. Работает и для WireGuard-туннелей (пришло из апстрима), и для AmneziaWG/AWG3 — там мы перенесли ту же механику в свою сборку.

  Заодно обновлена библиотека mieru — 3.34.1 → 3.35.0. В ней появился режим низкой энтропии (маскировка тела пакета против DPI, который ловит шифрованный трафик по «слишком случайному» содержимому). Режим выключен по умолчанию и включается только паттерном трафика от сервера, поэтому подключения к серверам `mita` прежних версий продолжают работать как раньше; если же паттерн его включает, сервер тоже должен быть не старше 3.35.0.

  Разборщик подписок в панели обновлён до той же версии mieru. Иначе импорт клиентского JSON от панели mieru молча терял бы новую настройку: незнакомые поля при разборе отбрасываются, и туннель к серверу с включённым режимом оставался бы без трафика без единой ошибки в журнале. Импорт `mieru://`- и `mierus://`-ссылок и подписок Clash этому не подвержен — там паттерн переносится как есть.

  **Туннели hysteria2 теперь маскируются под Chrome.** QUIC-хендшейк по умолчанию повторяет хендшейк браузера: DPI сложнее выделить hysteria2 из обычного трафика. Цена — окна приёма QUIC теперь тоже как у Chrome, а они меньше прежних (поток 8 → 6 МБ, соединение 20 → 15 МБ): на очень быстрых каналах это может стать потолком скорости. Вернуть прежнее поведение отдельному туннелю можно полем `"disable_chrome_parrot": true` в его конфигурации sing-box.

  Две комбинации TLS такая маскировка не переживает и обрывает подключение: `disable_sni` без `insecure` и клиентский сертификат. Такие туннели панель помечает `disable_chrome_parrot` сама — и новые, и уже сохранённые, при первом запуске после обновления. Править конфигурацию руками не нужно, тем более что у туннелей из подписки правка не пережила бы её следующее обновление.

- **FreeTurn обновлён до 2.1.1-1** — установка из панели ставит сборку нашего форка поверх апстрима `v2.1.1`. Из апстрима: решатель VK-капчи приведён в соответствие с текущей версией виджета (прежний уже расходился с ним в запросах и подписи), попытки слайдера разнесены по дорожке, а эскалация «чекбокс → слайдер» перестала жечь персону — то есть капча в среднем решается с меньшего числа заходов. Все наши доработки перенесены: пять авто-раундов, один слот капчи на роутер, отсутствие фатала на холодном старте, VKCalls-путь в обход капчи и время в журнале по часовому поясу роутера.

  Кто уже пользуется FreeTurn — карточка предложит обновление; старая версия продолжает работать, пока обновление не запущено.

- **AWG3: на простаивающем туннеле стороны больше не перебрасываются keepalive'ами** — при включённом `ContentPaddingAddition` отправитель дописывает padding и к keepalive, поэтому тот доезжает не пустым. Обе стороны считали его данными и заводили в ответ собственный keepalive, тоже с padding'ом. Прошлая сборка чинила только приём, теперь исправлены обе стороны. Видимые следствия: на простое пропадает лишний трафик и мусор `packet with invalid IP version` в журнале.

## [2.16.5] - 2026-08-02

### Исправления

- **Перезапуск интерфейса в NDMS больше не выключает туннель насовсем** — NDMS сам опускает и поднимает интерфейс (например, когда его ping-check не досчитался ответов; такой перезапуск настраиваем ему мы же), и делает это теми же событиями, какими сопровождается ручное отключение в веб-интерфейсе роутера. Мы принимали такое событие за намерение пользователя: туннель останавливался, статические и клиентские маршруты снимались, а в настройках он помечался выключенным. Обратно его не поднимало ничто — периодической сверки, возвращающей туннели к заданному состоянию, в демоне нет, а единственный автоматический путь наверх, событие «интерфейс снова включён», из опущенного нами же интерфейса прийти уже не мог. Туннель лежал до тех пор, пока владелец не включал его руками.

  Теперь событие о выключении выдерживается несколько секунд, и перед остановкой мы спрашиваем NDMS напрямую, что с интерфейсом сейчас: включён — значит это перезапуск, и туннель не трогаем. Прямой вопрос спасает и тогда, когда событие «снова включён» до нас не дошло или пришло позже. А если оно приходит ровно в момент нашей остановки, оно больше не теряется: дожидается её конца и поднимает туннель обратно.

- **Галочка debug в журнале WDTT больше не ломает запуск сервера** — переключатель достался журналу WDTT от FreeTurn, но `wdtt-server` флага `-debug` не понимает: разбор аргументов сразу завершал процесс с ошибкой, и сервер не поднимался, пока `debug` не убрать из `wdtt.json` руками. Подробного лога у бинаря нет вовсе, поэтому переключатель убран.

- **Удалённый сервер больше не заставляет роутер писать ошибку в журнал каждые полминуты** — тумблер захвата входящего трафика на карточке WireGuard-сервера сохраняет ссылку на этот интерфейс в настройках маршрутизации sing-box, а удаление сервера её не снимало. Каждая сверка маршрутизации, а она идёт раз в тридцать секунд, пыталась превратить ссылку в имя интерфейса ядра и спрашивала о нём NDMS — роутер отвечал в журнал `unable to find WireguardN in "Network::Interface::Base"`. Убрать ссылку из веб-интерфейса было нельзя: тумблер исчез вместе с карточкой сервера. Теперь ссылка снимается вместе с сервером, а оставшиеся от прошлых удалений — при старте демона.

- **Роутеры на MIPS больше не уходят в цикл перезагрузок в kernel-режиме** — на всех моделях с процессорами MediaTek MT7621/MT7628 и EcoNet EN75xx первая же настройка AWG-туннеля роняла ядро. Модуль AmneziaWG 3.0 не инициализировал блокировку header protection, а на MIPS ядро собрано с реализацией read-write-семафоров, для которой неинициализированная блокировка означает разыменование нулевого указателя. На aarch64 та же самая нулевая структура читается как свободная блокировка, поэтому на моделях с MT7622/MT7981/MT7988 дефект не проявлялся и не был виден при проверке на стенде. Роутер перезагружался, при следующем старте настройка повторялась — и так по кругу.

- **Настройка исчезнувшего интерфейса больше не роняет ядро** — модуль обращался к блокировке внутри кода ошибки, не проверив его, поэтому `awg setconf` или `awg set` по удалённому интерфейсу (или по интерфейсу чужого типа, каким NDMS пересоздаёт `OpkgTun` после перезагрузки) вызывал панику. Сюда же приводил мониторинг туннелей: при потере связности он переприменял endpoint, не убедившись, что интерфейс ещё жив. Теперь ядро возвращает ошибку, а мониторинг не трогает интерфейс, который не удалось положить.

- **Junk-пакеты с `Jmin` больше `Jmax` больше не портят память ядра** — размер случайного пакета выбирался из диапазона, границы которого никто не сверял, и при перевёрнутом диапазоне он мог превысить выделенный буфер до 65535 байт. Ядро падало позже и в другом месте, что делало причину неочевидной.

Модули пересобраны из тега `v3.0.20260731-04` с этими тремя исправлениями; в самом теге они отсутствуют. Обновлённый модуль загружается после перезагрузки роутера — до неё ядро продолжает работать со старым.

### Новые возможности

- **Имена клиентов WireGuard-серверов в списке соединений** ([#639](https://github.com/hoaxisr/awg-manager/issues/639)) — имя клиента резолвилось только по MAC через таблицу устройств NDMS, а трафик из туннеля приходит без MAC: пиры показывались голым IP и в таблице, и в сводке «По клиентам». Теперь берутся те же источники, что уже питают монитор соединений sing-box: описания пиров системных WG-серверов по их адресу и managed-серверов по tunnel IP. - **Прямой переход в редактирование политики sing-box** ([#573](https://github.com/hoaxisr/awg-manager/issues/573)) — кнопка «Управление устройствами» была только в простом режиме и открывала список политик. Теперь она есть и в панели движка экспертного режима, а ведёт сразу в редактор текущей политики: вкладка «Политики доступа» принимает имя политики параметром адреса.

- **Вкладка «Политики доступа» доступна на всех прошивках и уровнях интерфейса** — вкладка скрывалась на KeeneticOS 4.x и ниже «Расширенного» уровня. Ограничение по версии было скопировано с соседней вкладки NDMS, где оно обосновано (dns-proxy с object-group есть только в 5.x); политики же работают одинаково на обеих ветках прошивки, и бэкенд их никогда не гейтил.

- **Поддержка DNS-механизма sing-box 1.14 в sb-router** — DNS-правила принимают `evaluate`/`match_response`/`race`/`speculative`, `ip_cidr` и `response_rcode`/`response_answer`/`response_ns`/`response_extra`; цепочки проверяются на согласованность до применения конфига. Новые поля редактируются в UI: в модалке DNS-правила действие выбирается из `Маршрут` / `Блокировка` / `Evaluate` / `Respond` (прежние подписи «Резолвить»/«Заблокировать» переименованы), под выбранное действие открываются только применимые поля — цель `evaluate` и тег ответа, матчеры по DNS-ответу (rcode, IP ответа, RR-записи), `race`/`speculative`; строки правил в обоих списках показывают действие цепочки и чипы `race`/`spec`. Трейс «Проверка DNS» учитывает цепочки: `evaluate` больше не считается финальным совпадением, а правила, матчащиеся по ответу, помечаются как статически непроверяемые с предупреждением, что вживую они могут перехватить запрос раньше найденного правила.

- **DNS-пресеты sb-router: «Отказоустойчивый» и «Анти-подмена»** — цепочки правил из механизма 1.14 собираются одним переключателем в панели «DNS-серверы» вместо ручной сборки четырёх правил. «Отказоустойчивый» опрашивает прямой и туннельный резолверы параллельно и отдаёт ответ первого успевшего (упавший резолвер перестаёт быть отказом); «Анти-подмена» переспрашивает через туннель только те ответы прямого резолвера, чей IP попал в редактируемый список подозрительных подсетей (сид — `0.0.0.0/32`, `127.0.0.0/8`, `10.10.34.34/32`, `10.10.34.35/32`), остальные отдаёт как есть; если прямой резолвер молчит вовсе, «Анти-подмена» доспрашивает через туннель, а не проваливается на финальный сервер — иначе при типовой настройке (финальный сервер = тот же прямой) защита от подмены молча выключилась бы. Правила пресета помечены бейджем «пресет», не редактируются и не удаляются вручную, а при каждой записи конфига переносятся в конец списка, чтобы добавленные позже пользовательские правила срабатывали раньше цепочки. Рядом — кнопка «LAN-имена → локальный DNS», которая одним нажатием заводит локальный DNS-сервер и правило для однословных имён. Пресет работает в обычном режиме sb-router; в режиме FakeIP карточка заблокирована.

### Исправления

- **Исключения DNS-правил больше не требуют совпадения с включённым доменом** — сервер отклонял exclude, если он не был поддоменом одного из доменов списка, и это же закрывало исключения для доменов из подписок. Проверка снята: запись уходит на роутер как есть, решение принимает NDMS. Это даёт обход известной особенности NDMS, где сопоставление идёт по суффиксу без границы по точке (правило на `x.com` захватывает `yandex.com`). Заодно исправлено давнее: исключения попадали только в первую object-group списка и для списков длиннее 300 доменов просто не срабатывали — теперь они есть в каждой группе.

- **Тулбар в режиме дашборда занимает всю ширину** ([#607](https://github.com/hoaxisr/awg-manager/issues/607)) — элементы жались к левому краю, справа оставалась пустота. Поиск и переключатели остались слева, кнопки действий прижаты к правому краю. Заодно исправлено переполнение на ширине 761–1000 пикселей, где тулбар вылезал за край экрана и кнопка «Создать» была недоступна: строка переносится, правая группа уезжает целиком.

- **Длинные имена туннелей в столбце «Маршрут»** ([#643](https://github.com/hoaxisr/awg-manager/issues/643)) — столбец был фиксированной ширины, под чип оставалось 76 пикселей, и имя обрезалось рубленым краем без многоточия начиная с 13 символов. Столбец теперь растёт за счёт свободного места, остаток режется многоточием, полное имя доступно в подсказке.

- **QoS-маршрутизация: таймаут UDP-сессии и анализ трафика теперь действуют и на классы DSCP** ([#554](https://github.com/hoaxisr/awg-manager/issues/554)) — sing-box склеивает файлы конфигурации по имени, поэтому правила QoS-слота идут раньше системных, а правило класса обрывает перебор: помеченный DSCP трафик не доходил ни до правила с таймаутом, ни до анализа трафика. UDP-сессии такого трафика не закрывались по простою вообще — таймаут, заданный на самом перехватчике, лишь помечает запись во внутреннем кэше sing-box, а выселяется она только при появлении новой сессии на том же перехватчике, — и в списке соединений у них не было ни протокола, ни домена. Теперь QoS-слот несёт собственные копии обоих правил, сужённые до своих перехватчиков, чтобы не перехватить DNS раньше системного правила. Заодно исправлена подпись пункта по умолчанию в «UDP таймаут сессии»: там 5 минут, а не 3 — значение подняли ещё до релиза 2.16.0.

- **FakeIP: маршруты в туннель больше не ставятся там, где sing-box 1.14 правило уже не матчит** — в 1.14 набор правил (`rule_set`) вливается в ссылающееся правило, только если состоит ровно из одного простого правила без `invert` и вложенного `rule_set`; в остальных случаях он проверяется отдельно и лишь после того, как совпали собственные условия правила (раньше совпадения складывались по ИЛИ). Поэтому правило вида «свой `ip_cidr` + набор» перестало ловить пакеты по IP: они уходили в `direct`, ядро возвращало их в tun по нашему же маршруту — и получалась петля. Такие наборы штатно порождает мастер «умного списка», когда в него смешивают домены и IP. Теперь петлебезопасность считается по тем же правилам, что и в sing-box: CIDR отправляется в туннель, только когда совпадение правила по этому адресу гарантировано.

- **TProxy: штатный NDM netfilter reload больше не пересобирает все правила и не «отравляет» UDP-потоки** ([#627](https://github.com/hoaxisr/awg-manager/issues/627)) — каждый reload (DHCP renew раз в пол-lease, изменение UPnP) сносил PREROUTING-джампы одной таблицы, а хук в ответ разбирал и восстанавливал обе; на время пересборки перехват отсутствовал. Хуже того, UDP-поток, чей первый пакет попадал в это окно, получал в conntrack прямой NAT в WAN c offload-шорткатом и обходил tproxy до конца жизни — для звонка это «меня перестали слышать до конца разговора». Теперь хук восстанавливает только реально сломанную таблицу из отдельного файла правил (окно сокращается до долей секунды), а после восстановления TPROXY новый скрипт `awgm-ctclean.sh` выселяет из conntrack успевшие утечь UDP-потоки (ценой одного пакета поток пересоздаётся уже через tproxy); он же вызывается после установки правил при старте движка. В policy-режиме выселение фильтрует ядро по connmark политики, в режиме «все устройства» — отбор по `mac=` (LAN-происхождение). Диагноз, механизм «отравления» и вариант фикса — [tomas1pit](https://github.com/tomas1pit) с контролируемыми экспериментами на NC-1812. Пакет получил зависимость `conntrack`.

- **Подписку снова можно удалить, когда на её outbound ссылается другой раздел** ([#633](https://github.com/hoaxisr/awg-manager/issues/633)) — если «VPN для устройств» (или композит маршрутизации) выбирал выход из подписки, её удаление падало с «Ошибка удаления (500): … could not isolate outbound», и подписка становилась неудаляемой: предварительная проверка конфигурации судила соседние разделы по состоянию на диске, где ссылка ещё жива, тогда как реальное применение конфига такие висячие ссылки на селекторы самолечит. Теперь проверка моделирует то же самолечение (не трогая диск): чинимые ссылки не блокируют операцию, а нечинимые (правило маршрутизации на удалённый выход, ручные правки в 90-user.json, селектор из одних висячих членов) по-прежнему честно отклоняются.

Настраиваются эти таймеры на стороне сервера (routebox); awg-manager их принимает и показывает.

Конвертация сверена с эталонными конфигами RouteBox.

- **Свой тег outbound'а у сводной группы подписок** ([#572](https://github.com/hoaxisr/awg-manager/issues/572)) — при создании группы можно задать имя outbound'а для конфига sing-box и правил маршрутизации (латиница/цифры/`._-`, до 32 символов) вместо случайного `agg-xxxxxxxx`; пустое поле оставляет автогенерацию. Тег валидируется и проверяется на коллизии с другими группами и подписками; после создания не меняется.

### Исправления

- **Подписки: эндпоинты одного сервера с разным транспортом больше не считаются дубликатами** ([#625](https://github.com/hoaxisr/awg-manager/issues/625), [#614](https://github.com/hoaxisr/awg-manager/issues/614)) — идентичность сервера считалась по протоколу, адресу, порту и credential (плюс SNI/reality short_id), поэтому записи, отличающиеся только ws-путём, Host-заголовком, gRPC-сервисом или режимом транспорта, давали один тег: при импорте подписки второй сервер отбрасывался как дубликат, при ручном добавлении — отклонялся. Ключ идентичности расширен полями транспорта (только там, где различения не хватало — теги остальных групп не меняются); ручные исключения пользователя у затронутых групп переносятся на новую схему автоматически.

- **VLESS-ссылки с параметром `encryption` больше не роняют разбор конфига** ([#603](https://github.com/hoaxisr/awg-manager/issues/603)) — sing-box не имеет поля encryption в VLESS-outbound и декодирует строго: одна такая ссылка в большой подписке стоила отдельного прогона `sing-box check` на каждый сервер, дренаж упирался в бюджет, и пользователь видел «слишком много неподдерживаемых серверов». Мусорные значения (`auto`, `zero`, шифры от VMess) теперь молча игнорируются; настоящий VLESS Encryption отбраковывается с объяснением — sing-box его не поддерживает, сервер всё равно не заработал бы. Экспорт ссылки этот параметр больше не несёт.

- **Мониторинг: «не измерено» больше не показывается как время отклика** ([#629](https://github.com/hoaxisr/awg-manager/issues/629)) — для NativeWG-туннелей латентность меряет отдельная проба, и её неудачи схлопывались в −1, которую UI считал значением: успешная проверка показывалась как «-1 ms», квадрат в полоске краснел, а −1 попадала в avg/min/max. Теперь неизмеренная латентность везде трактуется как «неизвестно»: прочерк в строках проверок, приглушённый столбец вместо красного, из статистики исключается; причина показывается один раз в карточке (методы handshake и disabled время не измеряют вовсе — это не сбой).

- **FreeTurn: обновления `-N`-сборок снова предлагаются, проверка GitHub убрана** — сравнение версий отбрасывало суффикс `-N` как pre-release (`1.8.0-2` и `1.8.0-3` считались равными), из-за чего апдейт не предлагался; теперь номер сборки учитывается. Заодно удалена проверка обновлений через GitHub upstream (недоступен из RU, результат нигде не использовался — установка идёт закреплённой версией с зеркала) вместе с баннером «Не удалось проверить GitHub».

- **Хвост stderr умершего sing-box захватывается до удаления pidfile** — исчезновение pidfile разблокирует старт преемника (tun-restart/watchdog), который очищает err.log; чтение хвоста после удаления могло поймать пустой или чужой вывод (фантомный lastError, сломанная OOM-эвристика). Ловилось флаком теста в CI.

- **Outbound'ы подписок и сводных групп больше не «редактируются» в маршрутизации** ([#572](https://github.com/hoaxisr/awg-manager/issues/572)) — generic-редактор outbound'ов физически не может менять сущности слота подписок (сохранение всегда падало с «outbound not found»), но UI предлагал карандашик и поля tag/типа/URL. Теперь редактирование для них заблокировано с подсказкой, где менять на самом деле; строка сводной группы показывает её название вместо сырого `agg`-тега и бейдж «группа» вместо «subscription».

- **«Пиковая скорость» показывала текущую, а не пиковую** ([#576](https://github.com/hoaxisr/awg-manager/issues/576)) — плитка в сводке туннелей и дашборде брала последнюю точку скорости самого нагруженного туннеля, поэтому в затишье расходилась с пиками графиков карточек на порядки. Теперь считается честный максимум суммарной скорости (↓+↑) по тому же окну истории (последний час), что рисуют графики.

- **«Некорректный ответ сервера» при создании/импорте IP-маршрутов** ([#578](https://github.com/hoaxisr/awg-manager/issues/578)) — swagger-спека мутаций static-routes (create/update/import) и client-routes (create/update/delete/toggle) объявляла списочный конверт, тогда как бэкенд возвращает одиночный объект; runtime-валидация ответов на фронте (появилась в 2.16.0) на этом падала, хотя сами маршруты сохранялись корректно. Аннотации приведены к фактической форме ответов; заодно выправлены спеки ещё 13 endpoint'ов, где объявлялся голый payload вместо конверта `{success,data}` (geo-expand, ndms/save-status, presets, resolve, router/staging, terminal/install, selective, subscriptions refresh/active-member/orphans) — валидацию они не роняли, но документировали неверную форму.

## [2.16.0] - 2026-07-17

### Новые возможности

- **Автоматическая установка обновлений по расписанию** ([#559](https://github.com/hoaxisr/awg-manager/issues/559)) — в настройках (продвинутый режим) появился блок «Автоматическая установка»: тумблер, интервал «каждые N дней» (1–30) и время «HH:MM». По расписанию **демон** проверяет и ставит обновление awg-manager, а sing-box догоняется до закреплённой версии (в том числе разовой сверкой через несколько минут после старта, если он отстал). Результат каждой автоустановки пишется в журнал приложения, а после самообновления причина перезапуска восстанавливается из метки на диске. Отдельная страховка: когда обновлений нет, слот не опрашивает репозиторий на каждом тике. Время слота считается в локальной зоне роутера (заодно это чинит и ежедневное обновление DNS-списков по времени, раньше работавшее в UTC). **Отката при неудаче нет** (будьте внимательны!).
- **Массовая смена выхода и download detour в sb-router** ([#558](https://github.com/hoaxisr/awg-manager/issues/558)) — режим выделения на страницах правил sing-box роутера (tproxy и FakeIP): чекбоксы на карточках правил и «Выбрать все», нижняя панель «N выбрано → выбрать выход → Применить» меняет outbound сразу у всех отмеченных правил одним запросом (в tproxy правки уходят в общий черновик и применяются кнопкой «Применить», в FakeIP — сразу, одной перезагрузкой движка вместо гонки по одному). То же для download detour у наборов правил: массовая смена detour у выбранных remote-наборов. Выбираются только правила с реальным выходом-туннелем — системные (sniff/hijack-dns) и правила «Напрямую»/«Блокировать» из массовой операции исключены. Валидация серверная и строгая: неизвестный тег выхода, не-маршрутное правило, не-remote набор или пустой выбор отклоняются целиком (**то есть весь пакет изменений**).

- **Соединения: редизайн страницы** — "бублики" по туннелям/назначению/клиентам, фильтры с чипами, группировка по клиенту/хосту, панель деталей и сброс отдельного соединения. Дополнительно видно вообще **все** соединения на роутере.

- **Интеграция FreeTurn** — TURN-туннель для обхода блокировок ([free-turn-proxy](https://github.com/samosvalishe/free-turn-proxy)):  управление из веб-панели (новый пункт меню FreeTurn, вкладки «Клиент»/«Сервер»). Полный набор флагов, живые логи процессов прямо в панели, генератор и декодер share-ссылок `freeturn://` (с опциональным вложением WireGuard-конфига и автосозданием туннеля при импорте). Бинари freeturn НЕ поставляются в пакете awg-manager — панель предлагает установку в один клик: загрузка закреплённой в билде версии из релизов апстрима с проверкой SHA256 (та же модель доверия, что у managed sing-box); для архитектур без закреплённой сборки остаётся подсказка по ручной установке.

- **IPv6 endpoint для NativeWG-туннелей через awg_proxy** — сервер AmneziaWG за IPv6-адресом теперь работает в проксирующем режиме (прошивки без нативного ASC). Модуль `awg_proxy.ko` понимает бракетированную форму эндпоинта `[2001:db8::1]:51820` в `/proc/awg_proxy/{add,del,list}`, создаёт per-family UDP-сокет и отправляет трафик через `udp_tunnel6_xmit_skb` (обязательная UDP-контрольная сумма, hoplimit из маршрута; DF-бита в IPv6 нет). Локальная сторона (клиент WireGuard → `127.0.0.1:порт`) по-прежнему IPv4-loopback. Двухстековые хосты по-прежнему предпочитают IPv4 (стабильность), IPv6-only домены резолвятся в IPv6. В форме туннеля IPv6-литерал указывается в квадратных скобках (подсказка в поле Endpoint; голый `2001:db8::1:51820` отклоняется с ошибкой).

- **Эксперт-редактор конфигурации sing-box** — пользовательский слот `90-user.json` с черновиками, валидацией (кросс-слот проверка тегов + `sing-box check` над снапшотом «как если бы применили») и подсветкой синтаксиса; правки не перезаписываются генераторами. В эксперт-режиме sb-router появилась кнопка «Редактор»: обзор всех слотов config.d с бейджами владельца («генерируется автоматически» / «пользовательский»), read-only просмотр системных слотов с подсветкой и копированием, для user-слота — полноценный редактор (номера строк, маркер строки с ошибкой JSON, Tab-отступы): Сохранить черновик → Проверить → Применить (debounced SIGHUP; изменение tun-inbound перезапустит движок) / Отменить черновик, плюс выключатель слота целиком без удаления содержимого. Массивы user-слота (outbounds/inbounds/правила) дополняют merged-конфиг последними; скаляры dns/route (final, strategy) отсюда не переопределяются (first-file-wins). Если применённый user-конфиг после удаления чужого outbound начинает ссылаться на несуществующий тег, reload пропускается (движок работает на старом конфиге), а причина всплывает в статусе роутера: «Пользовательский конфиг (90-user.json) ссылается на несуществующий тег … — правьте в редакторе конфигурации».

- **Импорт настроек VPN через JSON-файл mieru** ([#449](https://github.com/hoaxisr/awg-manager/issues/449)) — панели (RIXXX / Panel-Naive-Mieru) экспортируют настройки mieru каноническим JSON-конфигом клиента (формат `mieru apply config`), который раньше отклонялся всеми путями импорта. Теперь такой JSON принимается целиком — вставкой и загрузкой файла: в мастере добавления («Один сервер» и «Группа серверов» получили дроп-зону для .json/.txt/.yaml файлов) и в подписках (inline и по URL, включая превью выбора серверов). Учитывается `activeProfile`, лишние клиентские поля (rpcPort, socks5Port, loggingLevel и добавки панелей) игнорируются; TCP/UDP-привязки портов и portRange профиля дают те же outbounds, что и ссылка `mieru://`.

- **Панель Inbounds показывает все inbound'ы merged-конфига** — раньше вкладка «Inbounds» (fakeip) и панель «Inbounds» (tproxy expert) отражали только tun-in и device-proxy, хотя merged-конфиг содержит также mixed-входы подписок (`sub-*-in`), сводных групп (`agg-*-in`), туннелей и tproxy-входы QoS — в config-preview они были видны, но ни одна вкладка их не объясняла. Новый endpoint `GET /api/singbox/inbounds` читает слоты config.d по одному и атрибутирует каждый inbound источнику (подписка/группа/туннель/device-proxy/QoS/движок) с именем владельца; обе панели показывают полный сгруппированный список (управление device-proxy не изменилось), а входы, которые никто не питает (NDMS-прокси выключен или объект отключён), помечаются бейджем «резерв порта» с пояснением — порт сохраняется, чтобы при включении номера портов не менялись.

- **Regex-фильтры серверов подписки и сводные группы** ([#372](https://github.com/hoaxisr/awg-manager/issues/372)) — у подписки появились фильтры в стиле mihomo `filter:`: «включать только» и «исключать» (Go RE2, матч по имени сервера; lookahead не поддерживается — вместо `(?i)^(?!.*(RU)).*$` используется поле «исключать» с `(?i)(RU)`). Скрытые фильтром серверы не материализуются в sing-box и показаны отдельным блоком «Скрыто фильтром»; фильтры компонуются с ручным исключением, смена фильтра сразу пере-применяет подписку (для inline — повторный разбор сохранённого списка). Плюс сводные группы: один selector/urltest-туннель поверх серверов НЕСКОЛЬКИХ подписок с собственным фильтром, режимом (по умолчанию — авто-выбор быстрейшего), портом и NDMS Proxy; группы пересобираются в том же reload, что и любое изменение подписок, управление — в секции «Сводные группы» на вкладке подписок. Надёжность: стадия батч-коммита конфига сериализована между конкурентными операциями (плановый refresh больше не смешивается с CRUD подписок/групп в общем батче), тела запросов subscription-эндпоинтов ограничены 1 МБ через общий helper, сторы подписок и групп пишутся copy-on-write — при ошибке записи на диск память не расходится с файлом.

- **Настраиваемое время жизни сессии и вход по учётным данным Entware** ([#441](https://github.com/hoaxisr/awg-manager/issues/441)) — время жизни auth-сессии задаётся в настройках (`sessionTtlHours`, 1-720 часов, по умолчанию 24; скользящее окно, укорочение действует сразу на уже выданные сессии). Опциональный вход по системным учётным данным Entware (`entwareAuthEnabled`): пароль проверяется локально по `/opt/etc/shadow` (MD5-crypt/SHA-256/SHA-512-crypt, только stdlib) без обращения к NDMS `/auth` — роутер больше не шлёт уведомления о входе; при неудаче локальной проверки выполняется прежний вход через Keenetic. Защита от перебора: локальная проверка Entware добавляет поверхность офлайн-подбора, поэтому учитывается каждая неудачная попытка, в которой проверялись учётные данные (в том числе локальная Entware-проверка при недоступном роутере) — на каждую такую попытку начисляется задержка 300 мс, а после 5 с одного IP endpoint отвечает 429 в течение 30 секунд; учёт атомарный, параллельные запросы не обходят лимит. Недоступность роутера без проверки учётных данных не учитывается; ответы «пользователь не найден/заблокирован» выровнены по времени с неверным паролем (защита от перечисления пользователей).

- **QoS-классы по DSCP в sb-router** ([#371](https://github.com/hoaxisr/awg-manager/issues/371)) — трафик, помеченный DSCP-кодами (0-63, до 8 классов), направляется в отдельные выходы sing-box: классификация через iptables `-m dscp` в цепочках AWGM (per-class TPROXY/REDIRECT-порты 51281+/51301+), пары inbound'ов `tproxy-qos-N`/`redirect-qos-N` и управляемые правила маршрутизации по `inbound`. Классы редактируются в настройках sb-router (`qosClasses`); доступность xt_dscp отражается в статусе (`xtDscpAvailable`), при отсутствии модуля ядра или расширения iptables функция мягко отключается, не ломая движок.

### Улучшения

- **Карточка Inbounds (прокси для LAN-устройств) показывает человеческие имена выходов** — бейдж целевого выхода и пометка «сейчас: …» отображали сырые теги (`awg-sys-Wireguard1`), тогда как выпадающий список настроек — понятные подписи («Veesp SE · nwg1»). Теперь бейджи резолвятся через тот же каталог выходов и показывают те же имена; формат подписи сведён в один хелпер для списка и бейджей.

- **Рестарт и обновление awg-manager больше не перезапускают sing-box** — демон «переподключается» к уже работающему процессу: логи sing-box переезжают с пайпов на файлы в tmpfs (осиротевший процесс больше не умирает от SIGPIPE при первой записи в лог), а сверка конфигурации пропускает перезагрузку, когда применённый конфиг не изменился (раньше рестарт демона всегда дёргал sing-box, в режиме FakeIP — с полным перезапуском туннеля). Если конфиг изменился (например, после обновления) — выполняется обычная перезагрузка. VPN-соединения при рестарте/апгрейде панели больше не мигают.

- **Страницы «Туннели» и «Серверы» загружаются со скелетоном** — вместо спиннера на холодной загрузке сразу рисуется структура будущего контента (правильный режим отображения и число карточек с прошлого визита), которая заполняется данными по мере ответа роутера. Анимация уважает prefers-reduced-motion; скелет списка соединений в диагностике переведён на тот же общий стиль.

- **Страница соединений больше не грузит роутер на каждый опрос** — атрибуция правил (badge DNS-списков) читала у NDMS весь runtime-кэш object-group (сотни килобайт JSON, ~1 секунда работы ndm) на каждое обновление списка соединений: под открытой страницей это давало ~40% CPU awg-manager и постоянную фоновую нагрузку на RCI роутера. Теперь результат кэшируется на 30 секунд (данные меняются только когда DNS-правила резолвят новые IP — на свежести бейджей это не сказывается). Заодно ускорен разбор всех ответов RCI: проверка на конверт ошибки больше не парсит целиком большие успешные ответы.

- **Каталог наборов sb-router: пометки про композитные списки и наборы без правил** ([#450](https://github.com/hoaxisr/awg-manager/issues/450)) — сервисы, уже входящие в добавленный композитный список (например, Anthropic при добавленном «Все AI сервисы»), помечаются в каталоге угловым знаком и подписью «в {название}» с подсказкой «Уже входит в добавленный композитный список … Можно добавить и отдельно» — плитка при этом остаётся кликабельной (отдельный набор добавить по-прежнему можно). Задизейбленные плитки стали внятнее: «добавлено» теперь различает набор, на который ссылается хотя бы одно правило (route или DNS), и «добавлено, без правил» (добавлен как набор — не используется ни одним правилом); работает и в каталоге tproxy-эксперта, и на вкладке Rule sets режима FakeIP. В мастере правил (каталог сервисов) пресеты, чьи наборы уже есть в конфиге, получают недизейблящую пометку «набор уже есть — будет создано только правило»: мастер переиспользует существующий набор и дублей не создаёт.

### Прочее

- **sing-box** — бамп до 1.14.0-alpha.42 (совместимость с обновлённым mieru-патчем из [#459](https://github.com/hoaxisr/awg-manager/pull/459); xhttp-патч применяется без изменений). Смоук сгенерированных конфигов (tproxy и fakeip-tun, все слоты config.d) против нового бинаря: `sing-box check` и полный старт проходят чисто; наши генераторы НЕ используют конструкции, удалённые в 1.14 (legacy address filter в DNS-правилах, outbound DNS rule item, `store_rdrc`, `independent_cache` не эмитятся). Осталось два деприкейшена с удалением в 1.16 (только WARN в логе, миграция отдельным issue): `download_detour` у remote rule-set (→ `http_client`) и неявный HTTP-клиент через default outbound у remote rule-set без detour.

### Исправления

- **FakeIP не валится «unknown-outbound» из-за протухших членов композита** ([#567](https://github.com/hoaxisr/awg-manager/issues/567)) — пересоздание или переименование туннеля меняло его тег, а ссылки в fakeip-слоте (члены композитов, правила) никто не чинил и не охранял: включение FakeIP падало кросс-слот валидацией с откатом в «Выключен», и пересоздание выхода не помогало. Теперь: сохранение композита проверяет member-теги и называет несуществующие (в обоих режимах — FakeIP и TProxy); переименование туннеля переписывает ссылки и в fakeip-слоте (включая припаркованный); удаление туннеля, на который ссылается fakeip-конфиг, отклоняется с перечислением мест; перед включением FakeIP каталог AWG-выходов (15-awg.json) освежается, чтобы живой туннель не считался неизвестным из-за устаревшего файла.

- **Селективный перехват больше не «воскресает» в режиме FakeIP** ([#564](https://github.com/hoaxisr/awg-manager/issues/564)) — выключенный слот `19-selective-routes.json` самовольно возвращался из `disabled/` в `config.d/`, и его правила мерджились в работающий fakeip-конфиг. Причина: завершившаяся пересборка ipset включала слот по одному лишь наличию правил, а сами пересборки не проверяли режим — их запускали и API-ручка, и фоновое CDN-обновление, и применение правил при «спящем» (унаследованном из tproxy) флаге селектива. Теперь включённость слота и все точки запуска пересборки сверяются с реальной активностью селектива (движок включён + режим tproxy + флаг взведён); ручной запуск пересборки вне tproxy отклоняется с честной ошибкой.

- **Страховочный потолок памяти демона на 1ГБ-роутерах** ([#562](https://github.com/hoaxisr/awg-manager/issues/562)) — модели с ≥700МБ ОЗУ работали вообще без GOMEMLIMIT (тюнинг GC был только у 128-512МБ), поэтому любой аллокационный всплеск беспрепятственно доезжал до 90%+ памяти роутера. Теперь и им ставится мягкий потолок 256MiB (сильно выше рабочих пиков — на обычной нагрузке GC не напрягается); явные переменные окружения GOGC/GOMEMLIMIT по-прежнему в приоритете.

- **Демон больше не раздувает ОЗУ после ротации логов sing-box** ([#562](https://github.com/hoaxisr/awg-manager/issues/562)) — файл процесс-лога sing-box открывался при спавне без O_APPEND: после самоусечения лога на 4 МБ писатель продолжал с прежнего смещения, файл становился разреженным, и tail демона бесконечно перечитывал «дыру» из NUL-байтов, экранируя каждый байт в журнал — CPU до 50% и рост памяти до OOM (ускоряющийся, так как дыра растёт). Исправлено открытие (O_APPEND сохраняется при truncate) и добавлен фильтр NUL-байтов в tail — он же защищает уже запущенные sing-box со старым позиционным fd, живущие через адопцию после обновления.

- **TProxy: смена «UDP-таймаут сессии» применяется без перевключения движка** ([#554](https://github.com/hoaxisr/awg-manager/issues/554)) — новое значение доезжало до inbound'а, но системное правило `route-options` (перекрывающее короткие сниф-таймауты sing-box, [#469](https://github.com/hoaxisr/awg-manager/issues/469)) перегенерировалось только при включении движка: в конфиге оставался старый `udp_timeout`, и не помогал даже «Перезапустить». Теперь сверка доводит правило до нужного значения сразу после сохранения настроек (и лечит его при ручном дрейфе). Для режима FakeIP то же самое было исправлено ранее в этом релизе.

- **FakeIP: правило маршрутизации без явного `action` получает CIDR-маршруты в туннель** — правило, добавленное через API без поля `"action": "route"` (веб-интерфейс его всегда шлёт), sing-box исполняет как route, но защита от петель считала его «не-маршрутом»: IP-адреса из его rule-set'ов не получали маршруты в tun и шли мимо туннеля молча. Теперь пустой `action` трактуется как route везде, где это делает sing-box — заодно у таких правил заработало предупреждение о несуществующем outbound.

- **Карточки sing-box-подписок больше не перемешиваются** ([#525](https://github.com/hoaxisr/awg-manager/issues/525)) — список подписок отдавался в случайном порядке (итерация по map), и карточки на странице «Туннели» перепрыгивали при каждом фоновом обновлении (~раз в 30 секунд) и при перезагрузке страницы — можно было удалить не ту подписку. Теперь порядок стабильный: по названию без учёта регистра.

- **DNS-маршрутизация: включение NDMS-списка снова доезжает до роутера** ([#489](https://github.com/hoaxisr/awg-manager/issues/489)) — у списков с фолбэком «авто» выключение срабатывало, а включение оставалось только в интерфейсе AWG Manager: маршрут в прошивке продолжал висеть выключенным. Причин было две. Значение «авто» не восстанавливается из состояния роутера (NDMS не отличает его от «нет фолбэка»), из-за чего сверка считала такие маршруты вечно изменёнными и на каждом цикле пересоздавала их вместо штатного переключения флага — теперь «авто» нормализуется при сравнении, и включение/выключение идёт нативным `dns-proxy route disable` по index. Вторая: NDMS при пересоздании существующего маршрута сохраняет его флаг disable (проверено на 5.1.1) — теперь после любого пересоздания сверка перечитывает состояние и явно доводит флаг до нужного в обе стороны.

- **FakeIP: смена DNS-сервера, стека и UDP-таймаута применяется сразу** — сохранение этих полей в настройках sb-router на включённом режиме FakeIP не доезжало до движка (даже после рестарта демона) и срабатывало только при выключении/включении режима. Теперь сохранение перегенерирует fakeip-конфигурацию и перезагружает движок. Пулы адресов и MTU по-прежнему применяются при перевключении режима — они требуют пересоздания интерфейса и маршрутов.

- **Ошибки старта sing-box видны в журнале приложения** — FATAL-строки из stderr sing-box (ошибки старта, когда Clash API ещё не поднялся и штатный пересыл логов их не застаёт) теперь попадают в журнал (`/logs`, раздел sing-box), а не только в stderr самого демона.

- **Файловые логи процесса sing-box не растут бесконечно** — лог-файлы на tmpfs (`/var/run/awg-manager/sing-box.*.log`) усекаются при достижении 4 МБ; на debug-уровне при месяцах аптайма они больше не съедают tmpfs роутера.

- **FakeIP: восстановлено разрешение трафика в tun-интерфейс средствами NDMS** — при интеграции режима FakeIP из прототипа потерялась настройка firewall на OpkgTun-интерфейсе: там, где межсегментный трафик режется файрволом роутера (isolate-private и подобные политики), клиентский трафик и DNS-запросы не доходили до fakeip-интерфейса. Теперь при включении режима создаётся permit-all access-list `_WEBADMIN_OpkgTunN` с привязкой `ip access-group … in` и флагом auto-delete — ровно та же форма, которую генерирует веб-интерфейс Keenetic при разрешении доступа к интерфейсу (проверено вживую: permit → bind → auto-delete, каскадное удаление списка вместе с интерфейсом). Список снимается при выключении режима, откате неудачного включения и уборке сирот; после обновления awg-manager поверх уже включённого FakeIP список доставляется автоматически первой сверкой. ACL-команды сведены в единые NDMS-примитивы (ими же пользуется межсегментный доступ managed-серверов) — заодно ошибки этих операций, которые NDMS кладёт внутрь ответа, перестали молча проглатываться: неудачное правило доступа теперь честно всплывает, а не выглядит применённым.

- **Осиротевший интерфейс FakeIP больше не вгоняет роутер в вечный цикл перезапуска nginx** — если NDMS-интерфейс OpkgTun с настроенным `ip address` оставался после выключения FakeIP (сбой удаления, крэш посреди включения, fail-safe выключение), ndm ежесекундно пересобирал конфигурацию nginx (bind на несуществующий адрес → ошибка → регенерация → снова ошибка), постоянно съедая ~20% ядра и подвешивая ВЕСЬ RCI на секунды — веб-панель и все операции awg-manager начинали спорадически тормозить на 1–9 секунд (частая причина «awg-manager стал очень медленным» и warn'ов `perf: slow rci`). Теперь на всех путях отключения (штатное выключение, откат неудачного включения, reap) при провале удаления интерфейса его IP-адреса снимаются отдельным шагом — неудалённый интерфейс больше не оставляет опасный адрес; reap дополнен сканом по описанию (убирает осиротевшие OpkgTun'ы FakeIP, потерявшие учётную запись, вместе с их маршрутом пула) и выполняется не только на старте, но и на каждом цикле сверки — runtime-сирота лечится за полминуты без перезагрузки. Откат неудачного включения FakeIP доезжает до NDMS даже при обрыве клиента посреди операции.

- **Соединения: исправлены двойные badge DNS-списка и потеря соединений без исходящего интерфейса** — записи sing-box/tproxy (в том числе IPv6) без исходящего интерфейса в conntrack раньше терялись из списка вместо атрибуции по маршруту.

- **Rule-set'ы каталога переехали на зеркало repo.hoaxisr.ru** — списки vernette/rulesets раздавались через raw.githubusercontent.com, заблокированный у части российских провайдеров: sing-box молча не мог скачать remote-набор, и правила маршрутизации/DNS с ним не работали (частая причина «каталог не работает», в т.ч. по мотивам [#534](https://github.com/hoaxisr/awg-manager/issues/534)). Теперь 19 URL каталога указывают на зеркало `repo.hoaxisr.ru/rulesets` (источник — форк hoaxisr/rulesets с ежедневным синком upstream), существующие установки мигрируются автоматически при старте: URL в применённых sing-box-конфигах (все слоты) и DNS-подписках переписываются на зеркало без переприменения пресетов. В данные Discord добавлены подсеть `104.29.0.0/16` и голосовые порты `19200:19400` (в применённые DNS-списки Discord подсеть дописывается той же стартовой миграцией).

- **NativeWG: маска подсети из адреса интерфейса больше не заменяется на /32** ([#531](https://github.com/hoaxisr/awg-manager/issues/531)) — указанный в туннеле CIDR (например `172.25.1.2/24`) молча превращался в `/32`: при создании интерфейса маска была захардкожена, а при каждом старте синк адреса срезал суффикс до разбора маски — и перетирал даже ручную правку в веб-интерфейсе Keenetic. Теперь маска пользователя доезжает до NDMS (connected-маршрут на туннельную подсеть для LAN-to-LAN работает); адрес без маски по-прежнему получает `/32`. Помните: маска интерфейса задаёт только маршрут — что пропустит WireGuard, решает AllowedIPs пира.

- **Движок маршрутизации больше не выключается сам из-за недоступного RCI** ([#523](https://github.com/hoaxisr/awg-manager/issues/523)) — периодическая сверка трактовала ЛЮБУЮ ошибку чтения метки политики (включая транзиентную недоступность RCI при ранней загрузке или shutdown-гонке во время перезагрузки роутера) как «политика удалена» и молча делала fail-safe выключение: снос перехвата, парковка слота, `enabled=false` без записи в журнал и без авто-восстановления — после перезагрузки тумблер оказывался в «выключено». Теперь fail-safe срабатывает только когда NDMS ответил и политики действительно нет; транзиентная ошибка оставляет состояние нетронутым и ретраится следующим тиком. Причина fail-safe пишется в журнал, а каждое выключение движка (включая по кнопке) оставляет запись в журнале. Закрыт и смежный тупик: если слот конфигурации движка запаркован (rollback неудачного включения), а цепочки перехвата живы (netfilter.d-hook восстановил их из сохранённых правил), сверка считала состояние здоровым «installed» и бесконечно ждала watchdog, которому нечего чинить — теперь запаркованный слот распознаётся как дрейф и лечится полным включением (перепромоут слота + переустановка перехвата); при мёртвом процессе лечение откладывается на тик после его оживления watchdog'ом, чтобы не задерживать fail-closed блокировку. Тот же дрейф закрыт и в режиме FakeIP: запаркованный слот конфигурации возвращается в merged-конфиг и при живом движке (раньше — только при мёртвом).

- **Импорт mierus://-ссылок с дополнительными портами/диапазонами** ([#516](https://github.com/hoaxisr/awg-manager/issues/516)) — ссылка вида `...&port=2012&port=2012-2022&protocol=TCP` (один `protocol` на несколько `port`, так экспортируют панели) отклонялась с ошибкой «mismatched number of port and protocol parameters»; теперь единственный `protocol` применяется ко всем портам. Заодно исправлен собственный экспорт «Копировать ссылку»: он генерировал именно такой неканоничный формат, и ссылка не импортировалась обратно — теперь `protocol` пишется парой к каждому `port`, как в эталонном клиенте mieru.

- **NativeWG-туннели больше не делят лимит 7 ID с kernel-AWG туннелями** — раньше оба backend'а получали ID из общего пула `awg10..awg16` (7 слотов), хотя потолок 16 — прошивочное ограничение индекса OpkgTun и к NativeWG отношения не имеет (его NDMS-интерфейс — `WireguardN`, в OpkgTun не отображается). NativeWG-туннели вымещали kernel-AWG из дефицитного диапазона и сами не могли превысить 7 даже в одиночку. Теперь у NativeWG собственный неограниченный сверху диапазон ID (`awg20+`), а реальную ёмкость задают честные пределы: до 100 интерфейсов Wireguard в NDMS (индексы `Wireguard0..99`, ранее искусственно ограничивались десятью) и до 16 одновременных туннелей с обфускацией через awg_proxy (слоты kmod; предел срабатывает при СТАРТЕ туннеля на прошивках без нативного ASC и сопровождается понятным сообщением, создание интерфейсов он не ограничивает). Лимит kernel-AWG (7 туннелей, `OpkgTun10..16`) — прошивочный, без изменений. Существующие NativeWG-туннели со старыми ID `awg10..awg16` продолжают работать без миграции — kernel-аллокатор просто пропускает занятые ими номера.

- **Прокси устройств с выходом через композит роутера (vpn/vpn2) при выключенном движке маршрутизации** ([#465](https://github.com/hoaxisr/awg-manager/issues/465)) — ломались и маршрутизация, и отображение. При выключении движка слот 20-router паркуется, композиты пропадают из merged-конфига, и авточистка висячих ссылок перед каждым reload молча вырезала vpn/vpn2 из селекторов device-proxy вместе с их `default` — sing-box уводил трафик в произвольный выживший член селектора, а карточка инбаунда показывала этот runtime-тег как якобы настроенный выход (последний переключённый инстанс выглядел «правильным» лишь до следующего reload). Теперь: (1) генерация слота 30 сама не эмитит ссылки на теги выключенных слотов — при недоступном композите селектор получает его default-член (нет default'а/недоступен → первый член → direct), т.е. трафик идёт по намерению пользователя, а сохранённый выбор не трогается и восстанавливается при включении движка; (2) включение/выключение движка (и смена режима tproxy/fakeip) синхронно перегенерируют слот device-proxy ДО reload, так что авточистке нечего вырезать, а если она всё же что-то режет — пишет warn, а не молчит; (3) карточки инбаундов показывают НАСТРОЕННЫЙ выход (как «О устройстве»), живой selector.now — отдельной пометкой «сейчас: …», деградация — явной пометкой «выход недоступен — через …» (новые поля `degradedOutbound`/`fallbackTag` в runtime-ответах прокси). Попутно: стартовый reconcile device-proxy перенесён после подключения каталога выходов роутера — раньше на каждой загрузке он считал композиты удалёнными и выключал ссылающиеся на них инстансы, стирая выбранный выход.

- **Валидация «как будто применён» для выключенного целевого слота** — CheckMerged/ApplyDraft теперь всегда включают целевой слот в снапшот `sing-box check`, даже если он в данный момент выключен: черновик валидируется «как будто применён и включён», в согласии с кросс-слот проверкой. Раньше применение черновика к выключенному слоту проходило мимо `sing-box check` (затрагивало и staging роутера на выключенном слоте, и user-слот эксперт-редактора). Порядок apply у user-слота изменён на «применить, потом включить»: провал валидации оставляет припаркованный слот выключенным, а его старый конфиг — нетронутым. Попутно: конфликт тега подписки с пользовательским слотом при обновлении подписки падает сразу с честной причиной («конфликт с пользовательским слотом 90-user.json: тег … уже занят — переименуйте outbound в редакторе конфигурации») вместо непрозрачной ошибки изоляции; advisory-предупреждения валидации (например, route.final задан несколькими слотами — sing-box молча оставит первый) доезжают до ответов check/apply эксперт-редактора и показываются отдельным жёлтым блоком; включённый, но содержательно пустой 90-user.json больше не удерживает и не запускает процесс sing-box.

- **sing-box в режиме маршрутизации теперь перезапускается автоматически после падения** ([#456](https://github.com/hoaxisr/awg-manager/issues/456)) — вотчдог проверял только легаси-туннели (10-tunnels.json) и при пустом списке выходил до liveness-проверки, поэтому упавший (например, убитый OOM-killer'ом) процесс в tproxy/fakeip-режиме оставался лежать до ручного «Перезагрузить». Теперь предикат перезапуска — активная работа оркестратора (router / device-proxy / подписки / туннели), а reconcile самих режимов (tproxy и fakeip) дополнительно поднимает мёртвый процесс сам (defense in depth). Против crash-loop добавлен backoff: 3 быстрых перезапуска за 10 минут — сразу, дальше экспоненциальная пауза (1→2→4 мин, кап 15 мин); сброс после «здорового» аптайма ≥5 мин или ручного управления, ручной «Перезапустить» не подавляется. Backoff применяется и к легаси-туннелям — раньше вотчдог перезапускал упавший процесс каждые 30 секунд без ограничений. Наблюдаемость: SIGKILL без stderr классифицируется по dmesg как OOM-kill с понятной причиной («роутеру не хватило памяти…»); панель движка показывает «Падений за 10 мин», причину последнего падения и до какого времени приостановлен автоперезапуск. Попутно закрыт пробел fakeip-реконсайла: drift-heal больше не воскрешает движок, остановленный пользователем вручную.

- **Пересборка selective-ipset больше не падает по фиксированному таймауту при медленной, но идущей работе, а «живую», но затянувшуюся пересборку теперь можно отменить из UI** — раньше фоновую пересборку (API `POST /rebuild` и авто-запуск при старте/reconcile) обрывал настенный дедлайн 10 минут, хотя на медленном MIPS-роутере с большим списком доменов работа честно продолжалась. Теперь продолжительность ограничивает stall-guard по прогрессу: отмена — только если 4 минуты подряд нет ни одного сигнала прогресса (смена фазы, собранный CIDR, завершённый DNS-резолв хоста/матчера, каждая ipset-команда и restore-чанк, материализация rule-set'ов и периодический тик geosite/geoip-скана), плюс абсолютный предохранитель 2 часа от «вечно живой» пересборки. Сигналы прогресса и время простоя считаются по монотонным часам — NTP-скачок посреди boot-пересборки не даёт ни ложного «нет прогресса», ни подавленного срабатывания. Сообщение об остановке различает причины и несёт последний прогресс («нет прогресса 4 мин подряд (фаза resolving, последний матчер …)»). Отмена пересборки из UI: в модальном окне пересборки появилась кнопка «Отменить пересборку» (`POST /api/singbox/router/selective/rebuild/cancel`) — ограниченный ручной выход из медленной, но живой пересборки, которую stall-guard легально не трогает; отменённый прогон завершается событием «пересборка отменена пользователем», staging-набор не подменяет живой. Попутно: подняты тесные exec-таймауты ipset-команд (restore одного чанка 60 с → 180 с, управляющие команды create/flush/swap/destroy/list 30 с → 120 с — нагруженный роутер с maxelem=262144 в них не укладывался); decompile .srs подчинён контексту пересборки и собственному таймауту 5 минут (зависший decompile больше не переживает и stall-guard, и 2-часовой предохранитель, вечно удерживая heavyop-гейт); сбой счётчика записей после успешного swap больше не рисует ложное «ipset пустой — весь трафик в WAN» (честное «записей: н/д»); пост-обработка успешной пересборки (синхронизация маршрутов + перезапуск sing-box) ограничена 10 минутами, чтобы заклинившая другая тяжёлая операция не удерживала флаг rebuilding бесконечно.

- **Rule-set'ы из geosite.dat не срабатывали на домен верхнего уровня** ([#448](https://github.com/hoaxisr/awg-manager/issues/448)) — при создании набора правил из .dat-файла все записи geosite конвертировались в `domain_suffix` с ведущей точкой (`.chatgpt.com`), который в sing-box матчит только поддомены — сам `chatgpt.com` мимо правила уходил в `final`. Конвертация переведена на типизированное извлечение v2ray-типов: RootDomain теперь даёт `domain_suffix` + точное `domain` для апекса (как в официальных конвертерах geosite→srs), Full — точный `domain`, Plain — `domain_keyword`, Regex — `domain_regex`. Скомпилированные старым кодом .srs-кэши инвалидируются автоматически (версия формата в meta.json); просмотр geo-файлов не затронут.
- **Файлы rule-set'ов не удалялись с диска** ([#448](https://github.com/hoaxisr/awg-manager/issues/448)) — удаление или переименование набора правил оставляло его артефакты (`rule-sets/inline/*.json|.srs`, `rule-sets/dat/*.json|.srs|.meta.json`) на диске навсегда. Теперь после успешного «Применить» и один раз на старте демона выполняется сборка мусора: удаляются файлы, на которые не ссылается ни активная конфигурация, ни pending-черновик (router и fakeip-слоты); отложенное удаление в черновике по-прежнему сохраняет файлы до применения, токен dat-эндпоинта и незавершённые компиляции не трогаются.
- **Клик по названию rule-set удалял первый чип** ([#446](https://github.com/hoaxisr/awg-manager/issues/446)) — в модалке DNS-правила поле «Rule sets» было обёрнуто в `<label>`: клик по любой не-интерактивной части (названию набора) браузер форвардил в первый labelable-элемент — крестик первого чипа, «случайно» удаляя его. Обёртка заменена на `div`, а ChipMultiSelect дополнительно гасит дефолтный label-форвардинг.
- **Панель дашборда туннелей на мобильных** — переключатель «Сплошной/Разделы» рисовался с наезжающими друг на друга подписями («СплошнРазделы»): кнопки сегмент-контрола сжимались ниже ширины текста без обрезки, и текст выползал на соседнюю кнопку — теперь подписи обрезаются с многоточием. Контролы панели скомпонованы компактнее (≤4 строк): тег-фильтр и действия (Экспорт) делят одну строку 50/50 вместо двух полноширинных.

- **OOM при пересборке selective-ipset на больших списках** — импорт geosite-масштаба (сотни тысяч матчеров) убивал демон по памяти: резолвер запускал по горутине на каждый матчер, а весь список доменов и IP материализовался в RAM. Пересборка переведена на потоковый конвейер (сбор правил → ограниченная очередь → фиксированный пул DNS-воркеров) — пиковое число горутин теперь ~14 вместо сотен тысяч (бенчмарк 80k матчеров: суммарные аллокации ~44MB, 200k: ~53MB, пик горутин неизменен). Введены лимиты: 100 000 уникальных доменных матчеров на пересборку и 65 536 host-маршрутов в оверлее 19-selective-routes.json — при превышении список усекается с явной пометкой «список усечён» в итоговом сообщении и в снапшоте (`truncatedMatchers`/`truncatedRoutes`), а не валит демон. Для роутеров с 200–700MB RAM (256/512MB-модели) добавлен GC-тюнинг: мягкий `GOMEMLIMIT=96MiB` + `GOGC=50` (ранее — никакого лимита; `/system/info` теперь показывает лимит вместо «Unlimited»); явно заданные переменные окружения GOGC/GOMEMLIMIT по-прежнему имеют приоритет.

Отдельный слот конфигурации, изолированный CRUD, инспектор DNS-маршрутов, авто-реконсиляция и очистка осиротевших ресурсов (PR [#402](https://github.com/hoaxisr/awg-manager/pull/402)).

## [2.12.3] - 2026-06-10

Главное: кратное снижение потребления CPU на роутере (под нагрузкой ~14x, в простое ~5x), нативный ICMP-мониторинг без вызова внешнего ping, ускорение загрузки состояния туннелей и переход на Go 1.26.

### Производительность

- **Кеш SHA256 бинаря sing-box** — `/api/singbox/status` больше не хеширует ~80MB-бинарь при каждом опросе (на MIPS это съедало целое ядро при открытом UI); хеш считается один раз и инвалидируется при обновлении бинаря (PR [#351](https://github.com/hoaxisr/awg-manager/pull/351)).

- **Модель CPU роутера** определяется один раз за процесс (раньше — regexp-скан системной библиотеки при каждом обновлении сведений).
- **Итог на живом mipsel: открытый UI 91–107% ядра → 7%, простой 11.4% → 2.1%.**

### Мониторинг

- **Нативный ICMP** (`x/net/icmp`) вместо exec `/opt/bin/ping` — pingcheck и матрица мониторинга шлют echo напрямую с привязкой к интерфейсу туннеля (PR [#348](https://github.com/hoaxisr/awg-manager/issues/348) в составе [#351](https://github.com/hoaxisr/awg-manager/pull/351)).
- **Устойчивый DNS-резолв проверок** — checkURL резолвится через DNS туннеля с кешем и fallback-цепочкой (tunnel-DNS → stale-кеш → системный).

### Сборка

- **Go 1.26.4 для всех архитектур** — снят пин Go 1.23 для MIPS (EOL); цена — бинарь mipsel больше на ~3.2MB, замерено и принято осознанно.
- **Зависимости**: x/net v0.55.0, protobuf v1.36.11.

## [2.10.8] - 2026-05-19

### Исправления

#### NativeWG реализация через awg_proxy.ko — серия фиксов 

На ряде серверов NativeWG туннель через `awg_proxy.ko` либо не устанавливал handshake вовсе, либо принимал первый handshake но через ~60 секунд сервер прекращал отвечать. На том же роутере и конфигурации kernel-AWG-туннель работал стабильно. Серия инкрементальных правок (kmod версии 1.1.3 → 1.1.6) приводит к байт-идентичности с reference `amneziawg-linux-kernel-module`:

- **MAC1 пересчёт на всех 4 путях handshake** (PR [#138](https://github.com/hoaxisr/awg-manager/pull/138) автор **@AYastrebov**) — `awg_proxy.ko` ранее пересчитывал MAC1 только на 2 из 4 типов handshake-пакетов (outbound init и inbound response), пропуская outbound response и inbound init. Когда сервер инициировал rekey или клиент отвечал на init, MAC1 не совпадал и пакет дропался. Спасибо Андрею за чистый референс-кросс-чек и точечный фикс. (kmod 1.1.3), именно этот PR вернул веру в возможность починить функционал.

- **HANDSHAKE_DSCP=0x88 на init/response** — reference выставляет AF41 DSCP на handshake-пакетах. Мы отправляли с TOS=0. Промежуточные узлы по пути дропали (особенно для CPS с DNS-shape контентом). (kmod 1.1.4)

- **DF=0 (Don't Fragment не установлен)** - приведено в соответствии с reference.

- **Удалён pre-ARP 0-byte UDP "probe"** — наша собственная оптимизация для прогрева ARP оказалась первым видимым пакетом от нашего источника к серверу. (kmod 1.1.6)

- **Inter-packet jitter в handshake-цикле** — наш kthread отправлял CPS+junks+init back-to-back за <1мс. Reference (через workqueue) даёт ~7-8мс на цикл. Добавлен `usleep_range(1500,2500)` между sendmsg-ами. (kmod 1.1.6)

### Под капотом (способ реализации)

- Новый mangle-фикс `AWGM-DNS-NOPOLICY` — `internal/singbox/router/iptables.go` + `lanbridges.go`. На каждом LAN-bridge с настроенным NDMS hotspot catch-all'ом эмитим правило `-m mark --mark 0x0 -m pkttype unicast --dport 53 -j MARK --set-mark <bridge-NDMS-catch-all-mark>`. Mark передаётся per-bridge — динамически читается из `_NDM_HOTSPOT_PREROUTING_MANGL` (не хардкод), что делает фикс корректным независимо от того какая именно policy назначена default в NDMS.
- `DiscoverLANBridges(ctx)` — пересечение `(NDMS hotspot mangle catch-all)` ∩ `(real Linux bridges in /sys/class/net/*/bridge)`. Это набор bridges где (a) device МОЖЕТ оказаться с mark=0 (через MAC-override) и (b) у NDMS уже есть готовая `_NDM_HOTSPOT_DNSREDIR` инфраструктура для этого mark'a. Исключает WireGuard tunnels и не-bridge интерфейсы.
- Пустой discovery (роутер без hotspot-конфига) → skip с warn'ом, install продолжается без DNS-NOPOLICY. Регрессия невозможна.
- `Reconcile` детектит изменение LAN-bridges (added/removed bridge, mark переназначен) → re-install iptables.
- netfilter.d hook расширен comment-tag scrub'ом — после NDMS reload правила DNS-NOPOLICY восстанавливаются без duplicate-accumulation.

  - **Боковая панель «Здоровье»** содержит запуск проверок системы (с подробной настройкой режима + opt-in restart-цикла), результаты последнего запуска с раскрываемым списком тестов, и DNS-проверку (свёрнутая по умолчанию).
  - Подвкладка **«Соединения»** сохранена с косметическим обновлением.
- **Новые тесты диагностики**:
  - **Расхождение времени** — сравнивает локальное время с эталонным сервером (HTTPS Date header). Расхождение >300с = FAIL, >60с = WARN. Wireguard handshake чувствителен к skew, частая причина «туннель не поднимается».
  - **rp_filter check** — для каждого работающего туннеля читает `/proc/sys/net/ipv4/conf/<iface>/rp_filter`. Strict-mode (=1) блокирует обратный трафик через VPN — частая причина «туннель up, но интернета нет».
- **Расширение страниц** — `Мониторинг` и `Диагностика` теперь занимают всю ширину экрана, без пустых полей по бокам. Свойство `width` контейнера: `narrow` (960px) для форм, `wide` (1440px) дефолт, `full` (100%) для terminal/grid.

### Изменения работы

- **restart-цикл диагностики теперь opt-in** — раньше при выборе режима «Полная» туннели автоматически перезагружались. Теперь это отдельный чекбокс «Включая restart-цикл», по умолчанию выключен. Полезно при отладке, но не сюрприз для пользователя.
- **Журнал диагностики**: SSE-перехват пропусков. При временной потере связи с роутером (сеть переключилась, бэкенд перезапустился) недополученные записи лога подтягиваются через `since`-параметр и сливаются в feed без дубликатов.
- **Параметр уровня логирования по умолчанию**: при первом открытии Диагностики берётся настроенный в системе уровень. При смене фильтра выбор сохраняется в `localStorage` и подгружается в следующих сессиях.
- **Маршрут `/pingcheck`** теперь редиректит на `/monitoring` (старые ссылки продолжают работать). Маршрут `/connections` удалён — соединения живут как подвкладка Диагностики.

  - Остановит туннель
  - Заменит Interface и Peer
  - Сохранит все настройки: имя, ISP-привязку, мониторинг, правила маршрутизации
  - Запустит туннель обратно

  DNS Route Failover — резервирование DNS-маршрутов

  Если в правиле DNS-маршрутизации указано несколько туннелей (primary + backup), AWG Manager
   теперь сам переключает трафик на резервный туннель, когда primary падает (определяется
  через PingCheck). При восстановлении primary трафик автоматически возвращается. В UI
  показывается toast-уведомление о переключении.

  Это обходной путь для бага в прошивках Keenetic, где встроенный механизм fallback в
  dns-proxy route работает ненадёжно.

  Комментарии в IP-маршрутах

  В правилах IP-маршрутизации теперь можно добавлять комментарии к подсетям через синтаксис
  1.2.3.4/32 !ASTelegram. Комментарии:
  - Парсятся при импорте .bat/.txt файлов (после строки маршрута)
  - Передаются в роутер через RCI (видны в нативном WebUI Keenetic)
  - Отображаются на карточке правила в виде тегов

  Идеально для импортов с группировкой по ASN или сервисам.

  Замена опросов на Server-Sent Events (SSE)

  Полная переработка обмена данными между frontend и backend:
  - Все обновления (статус туннелей, трафик, логи, мониторинг) приходят в реальном времени
  через одно SSE соединение
  - Убрано опрашивание раз в 5–30 секунд → меньше нагрузка на роутер, мгновенные обновления в
   UI
  - Графики трафика обновляются без задержек
  - При перезапуске сервиса страница автоматически перезагружается

  Orchestrator — единый мозг управления туннелями

  Полностью переписан слой управления жизненным циклом туннелей. Теперь все события
  (старт/стоп/удаление, события WAN, NDMS hooks, отказы PingCheck) обрабатываются единым
  orchestrator'ом, который принимает решения декларативно через таблицу состояний. Это
  устранило целый класс race condition'ов и сделало поведение предсказуемым.
